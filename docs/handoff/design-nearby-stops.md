# 设计：在“调整”里，替换一站 / 在一站之后插入「顺路的、行程里没有的景点」

> 2026-10-16 写。只做调研和设计，没有改任何代码和数据。
> 行号取自 2026-10-16 晚的文件；`tools/build_site.py` 另有 agent 在改，行号会漂，**以函数名为准**。
> 原型脚本在会话草稿目录（不进仓库），核心公式见文末附录 A，实现时重写成 `tools/build_nearby_pool.py` 和 `site_src/np.js`。

## 0 · 先说结论（executive memo）

**现状**：行程页每一站有个“调整”按钮，只能多待 / 少待 30 分钟、去掉这一站（`site.js` 的 `.adj` → 底部弹层 `.pk`）。想“多去一个顺路的地方”只能自己查，再去“加一天”。

**麻烦**：
1. 站点自己的“地点库”其实就是**所有线路里排过的站**（SIGHT 7763 条键和路线站点几乎一一对应，只有 53 个对不上）。没有一份独立的景点库。
2. 页面里每一行**没有坐标、没有数值时长**，车程只存在于“出发 → X”那行的文字里。客户端要重算，得先把这些数据放进页面。
3. 这个库在**中国热门城市很厚、国外和偏远地方很薄**：按“离这条线任一站 15 公里内、本线没有的景点”算，国内线路中位 3 个、20% 一个都没有；国外线路中位 0 个、52% 一个都没有（巴黎线 = 0，青藏线 = 0）。**只靠现有数据，一半线路点开会是空的。**
4. 自动查到的坐标里混着错点（翠华山被定位到西安市区一栋学生公寓，离真实位置约 30 公里），算“绕路”会得出荒谬的“+15 分钟”。

**要决定的**：候选从哪来；“顺路”怎么算；数据放哪、怎么按需加载；重算怎么接进现有的 `replan`；老用户存的数据怎么不坏。

**做法（一句话）**：离线脚本从现有路线站点建一个**干净的候选池**，按 3°×3° 网格切片成 `/assets/np/<格>.js`（总计约 1 MB，gzip 约 0.4 MB，点开才加载，一次 1–4 片，每片最大 25 KB）；页面每一行加上坐标等少量属性；新增一个可单测的 `np.js`（车程公式、绕路、排序、渲染一行）；`replan` 增加“插入 / 替换”两种操作，状态存新键 `zouni_np_<id>`（自带快照，旧数据不受影响）；UI 在现有“调整”弹层里加两个入口，选中后弹层内换成候选列表，一步选定、随时撤销。**国外和偏远线路的数据缺口，用独立的数据补写任务解决（不阻塞第一版）。**

### 1.2 页面里一行（一站）有什么
`tools/build_site.py::row_html`（≈14358）输出：
```
<li class="r see|fun|eat|dep|stay" [data-at="18:30"] [data-meal="l|d|b"] [data-in="1"] [data-cw="周几"]>
  <time>09:30</time><span class="dot"></span>
  <div class="rb"><p class="m">名字 <span class="icg"><a class="ic map" href=… data-ios=… data-and=…>…</a><a class="ic dp">…<a class="ic xhs">…<a class="ic yt">…</span></p>
  <p class="s">1 小时 30 分 · 门票… · 一句话 <button class="adj">调整</button></p></div></li>
```
- **没有坐标、没有数值时长、没有类型（只有 class see/fun）、没有“从上一站怎么来”的结构化数据。** 车程在紧挨着的 `li.r.dep` 行的 `.s` 文字里：`出发 → X` / `打车约 25 分钟 · 12 公里`。时长在 `.s` 文字里：`1 小时 30 分`。
- JS 运行时补的属性：`data-k`（行在原来那天里的序号）、`data-t0`（原始时间，`replan` 以它为基准平移）、`data-slack`（“回去歇一下 / 沿途慢慢走”这种可被吃掉的空当）、`data-fo/fs`（被“空档加的”改过名的原名）、`data-d0`（原始时长文字）。`site.js:356-362`。
- 每天 `<section class="day" id="dN" data-city data-stay>`，JS 补 `data-oi`（原来第几天；加的天有 `data-extra`、`data-after`）。`.sun[data-lat][data-lng]` 是当天的一个点（第一个有坐标的景点或城市），长线自驾页 `data-off="1"`（点不准）。
- 页面级：`article.trip[data-id data-n0 data-start data-app]`（`data-app` = amap/google，决定国内国外）、`section.go[data-go]`（含 `drv` 自驾、`ab` 出国）、`<script id="cands">`（加一天候选，`add_cands()` ≈14579）、`<script id="indoor">`（下雨换室内，`indoor_near()` ≈14666）、**`<script id="nearby">`（`near_list()/near_for()` ≈14681-14715：所有线路里 see/fun 站，离本线任一天的点 ≤25 公里、最多 30 个，字段 `n c lat lng dur`）**——这已经是本功能的雏形，现在只用来“空档加一个”（`site.js:342-399` 的 `fillHint`，把一个“沿途慢慢走/回去歇一下”空当行改名，**不改车程，也不重建图标**）。

### 1.3 客户端怎么重算时间表（`replan(sec)`，`site.js:356-402`）
- 输入（全部 localStorage，按“原来第几天 oi → 原来第几行 k”存）：`zouni_st_<id>` 出发时间 S、`zouni_drop_<id>` 去掉的行 D、`zouni_adj_<id>` 多待/少待分钟 A、`zouni_fill_<id>` 空档加的 F、`zouni_slow_<id>` 已废弃（启动时清掉）。
- 算法是**“按差值平移”**：每行新时间 = 原时间 `t0` + 累计平移。去掉的站把后面往前拉；多待把后面往后推；先吃掉 `slack` 空当；午饭不早于 11:30、晚饭不早于 17:30、`data-at` 定点不提前；原来赶得上、现在赶不上才提示（`.latewarn`，晚于 22:30 提示，可一键去掉最后一站）；`summary` 用 `出发行` 的 “N 小时 M 分” 文字加总“路上约 N”。
- **它只会改时间和隐藏行，不会新增行、不会改“出发 → X / how”文字。** 所以“插入 / 替换”不能直接套进去，要扩展（见 §6 步骤 5）。
- 车程文字是**编译期**写死的：`tools/compile_itineraries.py::leg()`（63-80 行）：直线 ×1.25；<1.3km 步行 4.5km/h；自驾线 <20km 开车 30km/h+5、≥20km 70km/h+10；乡下（国内非大城市、≥12km）包车 50km/h+10；市区 <20km 打车 25km/h+8，<60km 打车 55km/h+10，≥60km 包车 65km/h+10；全部按 5 分钟取整。作者写了 `via`（“自驾约 1 小时 30 分钟”）就用作者的。**国外城市内也走同一个表（“打车”），没有地铁模型。**

### 2.2 为什么不能直接拿来用：已经查到的脏数据
1. **错坐标**：`pois.json['西安|西安长安区翠华山景区']` 是 Nominatim 命中“交大财经社区西院-4号楼，翠华路”，离陕西历史博物馆 0.6 公里，实际翠华山在城南约 30 公里 → 原型里它是“+15 分钟顺路”。**闸**：非 curated、非“近似/人工”的坐标，`hit` 第一段必须和 q 或站名共享一个两字词，否则不进池（全库被拒 109 条，里面有真错也有繁简体误伤如“大龙湫/大龍湫”，可接受；误伤的列入白名单）。
2. **非景点**：机场、火车站、公路、环线、码头、营地、酒店、商场（“池袋阳光城”，type 标成 sight，一句话写“大型商场”）→ 名字和**一句话**都要查（`商场|购物中心|百货`）。
3. **只有晚上有意义的**（歌舞伎町“新宿夜晚的霓虹街区”、大唐不夜城、夜市）→ 打 `ev` 标，只允许插在当天最后一站之后。81 个。
4. **季节限定**（千鸟之渊“赏樱名所”，行程在 11 月）→ 名字+一句话含 樱/红叶/滑雪/雾凇/花海/薰衣草… 的 199 个，第一版**整体不进池**；第二版再按月份表放开。
5. **同一处的不同写法**：同名 15 公里内合并；名字互相包含且 1.5 公里内合并；≤120 米合并。去重后 8528 → 7080。另有 630 对 400 米内、名字不同的（大慈恩寺 vs 大雁塔 这类“一个院子里”）→ 运行时：与**当天**任一站 <250 米不出现，250–600 米出现但标“就在旁边”。
6. **同名异地** 63 组（开元寺 3 座、钟楼 2 座）。池里每条带 `城市+dest`，客户端按坐标距离过滤；排除“本线已有”用**名字 + 坐标 150 米**双判（不能只按名字，否则泉州的钟楼被西安的钟楼挡掉不影响，但反过来同城同名会漏）。
7. **“·”并列站**（“太古里 · 大慈寺”，37 个）：候选名取 `short(name)`（第一段），停留用整条的时长；第一版不拆。
8. **高海拔**：名字含 垭口/雪山/冰川/大本营/纳木错/羊卓/冈仁波齐/昆仑山口/唐古拉… 的 56 个标 `alt`（见 §4）。

### 2.3 干净候选池的构建（`tools/build_nearby_pool.py`，离线，输出 `data/catalog/nearby_pool.json` + 分片）
漏斗（全库实测）：
```
唯一 (城市,q)                                   9600
→ 类型 ∈ {sight park street museum fun temple beach mountain lake culture town}   9451
→ 没有定点 at（日出日落、演出、开船）            9182
→ 名字/q 不含 机场|车站|公路|环线|沿途|提车|还车|码头|渡口|口岸|酒店|民宿|营地|服务区|超市|商场|餐厅|夜市|…   9066
→ 有坐标                                        8614
→ 坐标不是“市中心/行政区级”，非 curated 的名字对得上   8528
→ 去重合并（同名15km / 包含1.5km / 120m）        7080
→ 去掉 商场类、季节限定                          6873    （其中 ev 晚上才有 81）
```
- 6873 条里：有一句话 6541（95%）· 有门票信息 679 · 高海拔 56 · 坐标是“近似”的约 5300（77%，**绕路分钟只当量级用，显示取整到 5 分钟**）。国内约 4800、国外约 2000。
- 再并入 niche `open`（约 157 个新增），字段补 `note`；`restricted/check/paused` 一律不进（假设 A3）。
- 每条字段：`id`（稳定哈希，名+城市+取整坐标）· `n` 名字 · `c` 城市（导航用）· `a,o` 坐标（保留 3 位 ≈110 米）· `t` 类型 2 字码 · `d` 停留分钟（该站在各线里时长的中位数；没有就按 `DUR` 表）· `s` 一句话（已用 `sight_of` 解析）· `q` 导航查询词 · `x`（门票短文、`预约` 标、`周一闭馆` 标、国外闭馆日）· `f` 位标：`alt` 高海拔 / `ev` 晚上 / `pop`（被几条线用过，取 log）· `ds` 目的地 id（国内外分流用，国外只在同国家内找）。
- **闸（`data_checks.py` 第 23 项）**：池里每条 ① 坐标在其 `ds` 目的地基点 ≤ 600 公里（国外 ≤ 400）；② 非 curated 的名字对得上；③ 不含黑名单词；④ 没有两条相距 <120 米；⑤ `s` 不含“商场”；⑥ 池条数不得比上一版少 5% 以上（防悄悄丢数据）。**反向注入**：把翠华山那条错坐标写回去、塞一个“某某火车站”、塞一个两份重复，三者都必须红。

## 3 · “顺路”的定义、公式、排序，和 5 条线路的实算

### 3.1 车程模型（沿用，不另造速度表）
`np.js` 里照抄 `compile_itineraries.leg()`（上面 §1.3），模式由**当天**决定：
`drive`（线路里有 `自驾`——页面 `data-go.drv` 或任一 via 以“自驾”开头）/ `rural`（国内、当天城市不在 `BIG_CITIES`）/ `city`。把模式写在 `section.day[data-lm]`，别让客户端猜。
**一致性闸**：`tests/np_parity.js`（node）+ `data_checks.py` 第 24 项：随机 300 对坐标 × 3 种模式，JS 和 Python 的 `(how, mins, dist)` 必须逐项相等；反向：把 JS 里 1.25 改成 1.3 必红。

### 3.2 绕路成本（单位：分钟）
记 `t(P,Q)` = 模型车程；`t0(P,Q)` = 页面上已写的那一段（读 `dep` 行 `.s` 里的 “N 小时 M 分”，作者写的或编译算的）；`f = clamp(t0(A,B) / t(A,B), 0.8, 2.0)`（山路比直线慢，把作者的经验按比例带到新路段；`t0` 缺失则 f=1）。
- **插入**（X 插在 A 之后、B 之前；B = 下一站，当天最后一站则 B = 住处，需要 `data-stay-ll`，没有就用当天城市中心）：
  `Δ = f·( t(A,X) + t(X,B) ) − t0(A,B)`，取 `max(0, …)`，显示取整到 5 分钟。
- **替换**（X 换掉 S；A = S 的上一站或当天起点，C = S 的下一站或住处）：
  `Δ = f₁·t(A,X) + f₂·t(X,C) − t0(A,S) − t0(S,C)`。
  **附加条件 `t(S,X) ≤ 30`**（必须是“同一片区”，否则会出现“把兵马俑换成市区的兵谏亭，省 20 分钟”这种数学上成立、产品上荒谬的候选；原型实测发现）。
  列表里只对 Δ ≥ +5 写“多 N 分钟”，Δ ≤ −10 写“省 N 分钟”，之间写“路程差不多”。**排序时不奖励“省路”**（`max(Δ,0)`），避免把必去的大景点排在最前被换掉。
- 阈值：**Δ ≤ 30 分钟**。
- 日预算（硬）：插入后该天非吃饭站 ≤ 4；**当天最后一行结束 ≤ 22:30**（沿用 `replan` 的迟到线）；**当天从第一行到最后一行 ≤ 10 小时**。客户端用 `replan` 的试算结果判断，不用估算（原型用 `Σ车程 + Σ停留 + 60` 估，会偏紧）。数据现状：现有线路每天站点数 1:1986 · 2:2467 · 3:1039 · 4:209 · 5:2（含吃饭类）；停留总和 p95 ≈ 5–6 小时。我**没有在代码里找到“1–4 站 / 10 小时”的硬规则**，只有 `tools/extend_days.py:17` 的“超 4 站”和 `replan` 的 22:30——本设计把它们定为这个功能的硬规则（假设 A5，请确认）。
- 关门时间：若候选有开放时间 `h`（如“9:00–17:00”），按**插入后的到达时间**检查：到达 + min(停留,60) > 关门 → 不进列表（列表阶段用上一站结束时间 + t(A,X) 估到达）；选中后若重排后仍晚于关门，弹层确认行里写“按现在排法 16:40 才到，17:00 关门”。

### 3.3 排序
```
score = −Δ⁺                         （Δ⁺ = max(Δ,0)，越顺路越高）
        + 6   如果有一句话             （有介绍的才好意思推荐）
        + min(6, 2·ln(1 + 被几条线用过)) （热门、有人排过）
        + 4   如果和被插入/被替换的那一站同类型 或 与当天标题共享类别词（寺/馆/园/街/塔/山/湖）
        − 3   如果 f>1.4（山路慢，估算不准）
        − 8   如果 坐标是“近似”且 Δ≥20（量级可信度低）
列表上限 5 个（假设 A4），不够 5 个就不凑。
```
没做的“当季”：版本 1 直接过滤掉季节限定词（§2.2-4）；版本 2 加月份表（赏樱 3–5、红叶/枫 10–11、滑雪/雾凇 12–2、薰衣草 6–7、荷花 6–8、油菜花 3–4、海滩 5–10）并读日期选择器的日期。

## 4 · 约束与风险

| 项 | 做法 |
|---|---|
| 每天站数、总时长 | 硬规则见 §3.2：非吃饭站 ≤4（仅限插入）、最后一行 ≤22:30、第一行到最后一行 ≤10 小时。超了：候选不显示；选中后若因后续平移超了，不允许选并在候选行写原因（“这天已排满”）。 |
| 高海拔 / 保护区 | 目的地 `elev ≥ 3000` 的线（`data-high`/`fit` 里已有“高海拔”提示）：**池里 `alt`=1 的条目永远不作为候选**（海拔不是我们能核实的数字，`05-注意事项` 要求“海拔数字不进 data”）；当天或候选所在地已 ≥ 3000 米的线，弹层顶一行“高原上多走一处会更累，先看今晚住的海拔”。niche 的 restricted/check/paused 一律不进。 |
| 预约 | 候选 `x.预约`=1：行里写“要预约”，选中后新行带 `.bkn`（和现有 `book_of` 同款），日历“预约提醒”自动覆盖；**不自动订**。 |
| 周一闭馆 / 国外闭馆日 | 候选带 `x.周一闭馆` 或 `FOREIGN_CLOSED` 的周几。客户端按**那一天的日期**（`.dpk` 日期选择器的值 + 天序）判断：当天闭馆 → **不进列表**（不是警告，因为用户没法在现场补救）；列表里没有日期把握（国内没标的博物馆 `INDOOR_RE`，只有软提示）→ 行里小字“周一多半闭馆”。选中后 `monday()` 现有提示（`site.js:~485`）会因为新行带 `data-cw`/周一闭馆文字自动出现——新行必须带这些属性。 |
| 门票与时间窗口 | 一行里写 `t`（“门票 约 60 元”）。选中后检查关门时间（§3.2）。**价格**：行程总价是估的参考价（`data-cost`：`tixPP` 是每个景点 ¥30–90 的粗估，按“天数比例”缩放）。第一版**不改总价**，只在新行显示门票；第二版：`tixPP += Σ新 − Σ旧`（解析不出价格的按 0），并在弹层里写“估价 ±¥N”。 |
| 国外线 | 池只取**同国家**；模式 `city`；`data-app=google` 时图标用 Google 地图/YouTube（`icons()` 的分支），不是高德；闭馆日用 `FOREIGN_CLOSED`（只有 10 项）→ 国外线候选**只有在 `x` 里有闭馆信息时才可信**，没有的写“出发前看官网”。国外城市内车程模型仍是“打车”（和现有行一致，**不是缺陷也不是修复项**）。 |
| 跨城、跨海 | ① 候选和 A/B 的直线距离 ≤ 35 公里才参与计算；② 岛屿线路（海南 `isl`、日本、东南亚）：候选所在“目的地 id”必须等于该线目的地；③ 不跨国；④ 已知渡轮/登机类站点（名字含 `码头|渡口|航班|机场|轮渡`）在黑名单里。**但直线 20 公里隔一道海湾的情况（香港–深圳、厦门–鼓浪屿）模型发现不了**——`BIG_CITIES` 里的这类城市，候选 `c`（城市）必须和当天站的 `data-city` 相同，第一版不允许跨“当天所在城市”。 |

### 7.2 差一点选中的方案，以及为什么放弃
| 方案 | 放弃原因 |
|---|---|
| **每页内嵌候选**（像 `#nearby`/`#indoor` 那样） | 1479 页 × 5–15 KB；长线页本来就 160KB–2MB；候选是“随选随用”的，不该每次载入都付；且更新池要整站重建。保留的 `#nearby` 用于空档加一个，不动。 |
| **按目的地 id 切片**（82 片） | 长线跨省要取多片，“邻省”要额外维护；最大片 57 KB。网格更通用。 |
| **在页面里给每个候选都预先算好每个位置的绕路**（建站时算） | 用户已经去掉/多待/改过后，A、B 变了，预算结果就错；而且体积 ×（站数）。 |
| **客户端整天重建**（把 `compile_itineraries` 的一天逻辑移植到 JS） | 那 150 行含午晚饭、回住处、定点空当、乡下包车等大量特例，移植几乎必然和 Python 不一致；`replan` 的“按差值平移”本来就够用，只缺“新增行”。 |
| **行内展开**（像手风琴） | 现有“调整/改出发/加一天”全部是底部弹层；手机上行内展开会推走整天的内容。 |
| **新增一个“附近”大按钮 / 单独页** | “少即是多”：每新增控件要说明删了哪个。复用“调整”弹层 = 零新增常驻控件。 |
| **候选只做“替换”不做“插入”**，或反之 | 你要的是两个都要；且两者共用同一套绕路算法，分开做反而重复。 |
| **实时调高德/Google 路线 API 算真实车程** | 无后端、有 key 泄露、限流、国内外两套；模型与现有行一致才不会“上一行写 25 分钟、下一行同样距离写 40 分钟”。 |
| **按用户当前位置推荐** | 这是行程规划页，不是出行中导航；“今天”视图是另一个功能。 |
| **自动识别“同一处”靠名字相似度/外部实体库** | 误判多；先用坐标 250 米 + 名字包含，再看真实反馈。 |

# 车程：照抄 tools/compile_itineraries.py::leg（直线×1.25；r5 取整到 5 分钟）
def leg(a, b, mode):
    d = km(a, b) * 1.25
    if d < 1.3: return '步行', max(5, r5(d/4.5*60))
    if mode == 'drive': return ('开车', max(10, r5(d/30*60+5))) if d < 20 else ('自驾约', r5(d/70*60+10))
    if mode == 'rural' and d >= 12: return '包车约', r5(d/50*60+10)
    if d < 20: return '打车', max(10, r5(d/25*60+8))
    if d < 60: return '打车约', r5(d/55*60+10)
    return '包车约', r5(d/65*60+10)

def detour_insert(A, X, B, t0_AB, mode):           # 在 A 之后、B 之前插 X
    f = clamp(t0_AB / leg(A, B, mode)[1], .8, 2.0) if t0_AB else 1.0
    return max(0, f*(t(A,X)+t(X,B)) - (t0_AB or t(A,B)))

def detour_replace(A, S, C, X, t0_AS, t0_SC, mode): # 把 S 换成 X
    f1, f2 = factor(A,S,t0_AS), factor(S,C,t0_SC)
    return f1*t(A,X) + f2*t(X,C) - t0_AS - t0_SC   # 另要求 t(S,X) <= 30

### 判断出来的风险
- **空状态会很常见**：国内线 60% 的站、国外 78% 的站点开“加一个”是空的；国外整条线没有的占 58%。这是 30 分钟阈值 + 数据厚度共同决定的，空状态文案和“这天已排满”那一种要认真写。
- 同城规则（`BIG_CITIES` 当天城市必须相同）在候选 `c` 是**线路里写的城市名**而不是地理城市时偏严：抽样里在范围内的候选有 21% 因此被挡（比如西安线里写成“咸阳”的）。要放宽，先想鼓浪屿/香港这种隔水的怎么拦。
- 84% 坐标是人工近似，绕路分钟显示取整到 5 分钟，排序里“近似且 Δ≥20 扣 8 分”；上海—杭州这片最密，近似坐标也最多。
- “换成”会把头牌换成省路的小景点（莫高窟 → 敦煌博物馆“省 50 分钟”、兵马俑 → 兵谏亭）：排序不奖励省路，但仍会出现；UI 要对 `p`（被几条线用过）高的被换站加提醒，或在列表里限制“新站 `p` 不得低于被换站的 1/4”。
- 开放时间只有 667 条有，其余不能判断是否关门；已关闭/整修的景点没有数据，第一版只靠“开放时间以官网为准”。
- 原型的当天时间表是估算（午饭 60 分钟、没有晚饭、起点用城市中心），只用来证明模型和空状态量级；页面里必须用 `replan` 试算。

### `replan` 怎么扩的（影响面最大的一处）
`replan` 的假设是“行是静态的，只改时间和隐藏”。没有改这个假设：每次 `replan` 开头 `npSync` = 先 `npRevert`（把这一天还原成静态页面，靠行上的 `data-np-*` 属性备份）再 `npApply`（按 `zouni_np_<id>` 重套）。套完给 `replan` 一本账：`ld` 每个车程行的分钟差、`rd` 每个被换的站的新停留、`vs` 每个锚点后面的虚拟行。`run()` 里：①`ex(r)` = 多待少待 + 被换站新停留 − 原停留 + 车程分钟差，汇进同一个累计平移 `shift`（没有顺路操作时 `ex(r)` 就是原来的 `A[k]`，**逻辑上逐位等价**）；②加的行紧跟锚点算时间（先一段车程，再停留），后面的行整体后推；③被改写过的车程行的下限是 5 分钟，其余仍是 15。加的行不进 `rowsOf / orig / timed`，所以 `data-k / data-t0` 的语义没变。

### 决策（和设计文档不同、或设计没写死的地方）
1. 候选上限 8（用户改的）；类型“图标” = 一字灰色小方框（寺 馆 园 街 景 山 水…），没有新画 SVG。
2. **“当天结束 ≤22:30”用 replan 自己的“这天几点结束”**（最后一行时间 + 它的跨度，就是页面上“这天要到 N 才结束”的那个数）：选完不会立刻冒红字。**“首尾 ≤10 小时”用第一行到最后一站结束**（晚饭、回住处不算），和 `nearby_prototype.py` 一致。标准日（9 点出发、傍晚回住处）本来就超 10 小时，所以“加一个”在这些天置灰——这是用户定的规则的直接结果，不是 bug。
3. 严格执行：超了就不可选。没有给“替换不比原来更糟”开例外。
4. 加一个 = 紧跟锚点（在它后面、午饭前），所以午饭可能被推到新站之后；新站吃掉“沿途慢慢走”这类空当。
5. 新车程分钟 = 模型 `leg()` × f（f 取自页面上原来那段的 `data-min`，夹在 0.8–2.0）；f=1 时和 Python 模型逐位相同。
6. 一条线最多 12 个操作（设计 A7）；每个操作自带快照；格式有版本 `v:1`；字段不对、版本不认识、锚点名对不上都当没有（锚点对不上提示一次并从存储里删掉）。
7. 被下雨换室内改过名的行、空档加的行、定点的站、加的站自己：不显示“换成/加一个”。
8. 存储里已有操作的页面，刷新时先显示原版、等 `np_model.js` 加载完再重排一次（会闪一下，只在有操作的页面）。
9. 候选的“一句话”继续用池脚本里解析好的（设计 §决策 1），没有在 build_site 里再跑 `sight_of`。

### 变更 · 预算规则放宽（2026-10-17，主会话决定）
**为什么**：原规则（非吃饭站 ≤4、结束 ≤22:30、首尾 ≤10 小时）让标准日的“加一个”大面积置灰。全站 1489 条线、5609 个有可调站的天实测，被预算挡掉 11.4% 的天（站数 198、22:30 39、10 小时 401）；国外 16.8%；西安第 1、2 天、东京第 2、3 天都在其中。
