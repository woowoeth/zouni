# 02 · UI 规范

总原则：**像一本杂志**，安静、留白、层次清楚；手机优先（iPhone 宽 390）；能少一样就少一样。

## 字体

| 用途 | 字体 | 说明 |
|---|---|---|
| 标题、片名、目的地名、分区名、导语 | `var(--serif)` = Noto Serif SC（只打包了 700、900 两个字重） | 网页字体按字切成两百多个小文件 |
| 正文、按钮、小字 | `var(--sans)` = Noto Sans SC，退回苹方 / 微软雅黑 | |

- 宋体的 `font-display` 是 **block**（等字到了再显示），**不要改回 swap**：swap 会让每次切页标题先显示系统字再跳成宋体（Jerry 投诉过“每次切换字体都会变一下”）
- 黑体保持 swap（和系统黑体长得像，看不出跳）

## 颜色和层次

变量：`--ink` 墨色（正文、标题）、`--sub` 灰（次要信息、标签）、`--line` 细线、`--red` 红、底色米色。

**红色只用在两类地方：**
1. 要点的：“改”、“要预约 ›”、“官网预约”、“携程订这家”、买票
2. 真要注意的提醒：快截止、晚了、限行

另外每天开头的大号日期数字（如“02”）保留红色，是每天唯一的视觉重点。
**其他一律墨色或灰色**：小标题（出发前、今晚住、懂一点、要办的事）、“01 02”序号、推荐 / 奢华档次、世界遗产 / 5A、国宝标签、镇馆之宝、纪录片片名、分区名。

三层层次（以纪录片页为例）：
1. 名字（吃的 / 国宝 / 景点）：墨色宋体粗
2. 集名、地点：灰色小字
3. 能去的行程链接：墨色细字，几条用“·”隔开，不带“›”，**不要下划线**（Jerry：“下划线真的很丑”）；频道切换标签也不画下划线，当前项靠加粗 + 墨色区分

## 对齐

- 页面左右边距统一 **20px**；所有文字的起点（小字、标题、导语、切换栏、分区标题）都在同一条线上
- 改样式后跑 `tests/webkit_align.py`，它量每段文字实际起点
- **教训**：不要复用通用类名（比如 `.kick`）去写某一页的样式——头图里同名的小字也会被改掉（出过一次 20px 错位）；新样式一律带页面前缀（`.where .kick`、`.chan .kick`）
- 外层已经有边距的元素，里面不要再加边距（走哪儿的切换栏出过 40px）

          华北                                    宋体 20px

- 片子页的“第一季 第二季 …”和影像方志的省份跳转条（`.chan .jump`）和走哪儿的月份条同款：灰块、当前项墨色底，吸顶，滚动时跟着高亮（site.js 末尾）。不要再做成文字加下划线
- 插图：跟片走目录每行右侧一张 60×80 封面，片子页顶部一张横幅（高 210px，居中偏下裁切）；走哪儿每张卡左边一张 44×58 缩略图（取该目的地第一条线的海报）。插图一律用 `tools/posters/` 的画法（渐变 + 主角 + 颗粒），别用图标或照片
- 片子页每条先写名字，灰字地点，再一行“好在哪”（`why.json`），最后才是排进了哪几条线（只写线路名，**不写“第几天”**——Jerry：我更关心好在哪、为什么要去、为什么要吃）
- 每个条目左边一张小插图（`tools/motifs.py`：30 个平涂符号 × 10 套配色，按名字里的字选符号，配色按 hash，页面只带一次 ~14KB 符号表），右上角是 导航 / 点评 / 小红书 三个灰色小图标（`icons()`，吃的按“地点 + 菜名”搜，国宝按博物馆，地点按“省 + 名字”搜，国外用谷歌地图）
- 片名本身以“跟着”开头的，标题写“《跟着书本去旅行》里的地方”，别写成“跟着《跟着…》走”
- 跟片走目录（`.toc`）：灰色序号 01–11、宋体 22px 片名、一行小字“说明 · 拍过 N 处”

## 行程页

- 每天开头只留“出发（可改）”和“日落”两格（日出删了）
- 纪录片那一行最多写两样，多了写“等”，地方最多两个
- 时间轴一行：时间 · 名字 + 图标；第二行灰字：时长 · 门票 · 一句话；博物馆多一行“镇馆之宝”
- “懂一点”：段首一行小灰字写地方名，下面正文
- 目的地页列表的导航 / 点评 / 小红书图标是**灰色**（三十行一排红图标太花）

## 图标和外部入口

- 导航（高德）、点评、小红书：凡是有名字的景点、吃饭的地方、酒店、目的地页列表都要有；小红书按“城市 名字”搜
- 手机：只调 App（`amapuri://`、`dianping://`、`xhsdiscover://`、携程 `ctrip://wireless/h5`），没装 1.6 秒后提示
- YouTube 搜索入口（`a.ic.yt`）：排在小红书图标后面，纯网页链接 `youtube.com/results?search_query=<城市 地点> 旅行`，没有 App 调起，电脑和微信里也显示（不受 `.noapp` 隐藏）。
- 电脑、微信内置浏览器：不显示这些入口；微信里第一次打开提示“右上角在浏览器打开”

## 写字的规矩

- 短句、具体：写“从西安坐火车约 6 小时，或者坐飞机”，不写“交通便利”
- 纪录片写“推荐 / 早上吃 / 讲过 / 拍过”；多季的片子标“第几季”，只有一季或查不到多季的（`SINGLE_SEASON`：河西走廊、跟着书本去旅行、话说长江、新丝绸之路、丝绸之路、中国影像方志、两个杂志榜单）不写“第一季”
- 不知道的不写；拿不准的写成能核实的说法（例：远程航线写“要转一次机，路上总共约 X 小时”）
- 不重复：同一信息只出现一次（时间轴和“懂一点”不说同一句）
- 不要多余入口和链接（“下一天”就是被删的例子）

## 深色模式（2026-10-14）
- 跟系统（`prefers-color-scheme: dark`），没有手动开关。`site.css` 末尾的 `@media (prefers-color-scheme:dark){:root{…}}` 只换变量：`--bg --ink --sub --mute --red --card --green --blue --line --line2 --ink2 --lead --okbg --okfg --warnbg`。`--pink` 不换（它是封面上的浅色字）。
- **写新样式要用变量，别写死颜色**：正文/次要字用 `var(--ink)` `var(--ink2)` `var(--sub)`；浅底深字的徽标用 `--okbg/--okfg`、`--warnbg`；线用 `var(--line)`。写死 `#3d3f3a`、`rgba(28,29,26,…)` 这类浅色主题颜色，深色下会读不清。
- 压在图片或固定深色块（封面、头图、色块 `tile`）上的字用 `var(--onimg)`（恒为奶白），**不要用 `var(--bg)`**（深色下 `--bg` 是近黑）。
- 海报、封面是 `<img>` 的 SVG，深色下保持原样（浅色画面嵌在深色页面里）。走哪儿的地图是内联 SVG，底色也是浅的。
- 验证：浏览器里 `resize_window` 设 `colorScheme: dark`，用页面里算文字与有效背景对比度的脚本扫（低于 3.2 的列出），主要页面都扫过为空。

## 少即是多（2026-10-15，只改展示、不删功能）
- 行程页前言：概览列表（“N 天，怎么排”）和每天标题重复，用 CSS 藏起来（脚本仍在用它，不能删 DOM）；路线图默认折成一行“看路线图”（`.mapfold`，点一下展开）；“怎么去、怎么回”和“出发前”两块视觉上合成一块。第 1 天顶部约 860px（原约 1440px）。
- 国外页“出发前”里每页都重复的护照有效期/保险套话折成一行“出境通用须知 ›”（`li.gen details`），勾选框保留。
- 不做：把图标收进详情面板、按地区隐藏图标（用户要求图标都保留）；删分享/打印等功能（用户要求功能不减）。
- 规则：任一核心任务的点击步数不增加；新增字/控件要先说明删了哪个。

## 长线自驾页（2026-10-16，`xl\d+a` 和 `xb96a`，`build_site.is_long`）
长线每天的 `city/navCity` 是**前一晚住的地方**，不是当天去的地方；下面这些都因此按“当天实际”来写：
- **“住X”**（概览每行、“住：A → B …”一行）用 `stay_city()`：`d['stay'][0].city` → `stayName` → `navCity/city`。订酒店、点评、导航的城市也是它。
- **不写“往年 N 月平均”**（`.cl` 留空、`data-clim='{}'`，JS 要找这个节点，别删）。
- **日出日落不显示**：长线的 `d.lat/lng` 是起点城市，算出来差几十分钟到两小时；`.sun` 带 `data-off="1"`，JS 不填、整格隐藏，也不拉天气预报。其余线路算不出（极昼极夜）时整格也隐藏，不留“—”。
- **时间轴只留有地点依据的行**：不显示固定的“18:30 晚饭”“出发 → 吃晚饭/住处 打车或步行”，也不显示按起点城市菜系拼的午晚饭（`place` 是 附近/沿途 的都去掉）；“X 里面 简单吃一点”留着，因为它点了地方。
- **开车 N 小时** = 当天所有 `自驾约 …` 累加（首段、站间、回住处都算，`drive_minutes`）；不足 45 分钟写“N 分钟”，0 的天不写；页头“最长一天”同源。
- **海拔** = 当天最高点：`max(住宿海拔, 当天今天部分的文字 / 站名里点到的垭口)`。垭口表 `PASS_ELEV` 在 `build_site.py` 开头，只写有把握的，**海拔数字不进 data**。最高点比住宿高 300 米以上写“今晚睡 X 米 · 今天最高 Y 米”（占整行，`.fx.wide`）。页头 fit、出发前、FAQ 的“最高到 N 米”取全线最大值（`r['maxElev']`）。文字里“明天/次日/第二天”之后的句子不算今天。
- “懂一点”/一句话按名字取文案时多一道 `long_text_ok`：两字键（西湖、室韦）嵌在别的地名后面（惠州西湖、瘦西湖）不取；文案里写“从X北上/出发/自驾”时 X 必须出现在当天上下文，否则不显示。被拒绝的记在 `build/long_collisions.txt`。
- 节目/榜单标签（`sj_for_trip`）按“地名词”匹配（`key_hits`）：键等于站名/标题里的一个词，或前面是词头/当天城市/“回、去”，后面不接江河湖海；不再是子串（珍珠海≠珠海、金沙江大桥≠金沙、当雄≠雄县、跑马山≠马山）。全站生效，不只长线。

## 首页（2026-10-16 第三轮：按场景走一遍后改的）

**先想场景再改**：A 手机第一次打开，3 秒内要知道“这是干嘛的、能做什么”；B 我有 N 天假；C 我已经知道去哪；D 随便逛；E 老用户回来看“我的行程”。

**从上到下的顺序（手机 390×844，首屏必须同时看到搜索框 + 频道四格（2×2）+ “替我挑三条”那一行）：**

```
封面（矮，330px）  走你 · 我的行程 · 封面故事（有图，没有 img 字段的线用 /img/p/<id>.svg）
搜索框             .hsearch   提交到 /where/?q=（场景 C：已知道去哪的人第一个碰到的就是它）
频道四格（2×2）    .chan2     走哪儿 / 跟片走 / 跟谁走 / 长线自驾（2026-10-17 加了“跟谁走”，三格改 2×2；唯一一个进 /long/ 的首页入口）
替我挑三条         .pick      默认折叠成一行（标题 + 已选摘要 + 展开/收起），点开是 4 行“标签 + 一排 chip”，选满三项出结果
现在去正好         #now       出发日期条（.datebar，原来压在封面上）→ 天数 chip → 卡片 → “再看 N 条”
下个月正好 / 长途和自驾 / 什么时候去都行
```

- **封面**：原来 `min-height:700px`，一整屏暗色大图 + “翻开”，搜索和频道被挤出屏幕；而且封面线没有 `img` 字段时整块是暗色（线上就是这样）。现在 330px；封面图和列表用同一套回退（`img` → `p/<id>`），封面只在“有海报”的当季线里挑（`_has_poster`）。出发日期条挪进“现在去正好”（它改的是这个列表，封面只是跟着换）。
- **替我挑三条**：功能不变（出发地 / 几天 / 和谁 / 出行方式，打分和 `localStorage` 不动），只是默认折叠。折叠头显示已选项（“北京 · 周末 2–3 天 · 自己或朋友”），点开 4 行，每行左边一个 36px 的小标签。**脚本要点开才能点里面的 chip**：`document.querySelector('.pick .pkh').click()`（`webkit_*` 和 `home_matrix_browser.js` 已加）。
- **卡片**（`item()`）：去掉每张卡一个黑色“翻开 ›”按钮——标题是链接，`h3 a::after` 铺满整张卡，整张卡可点（图片那个链接 `tabindex=-1 aria-hidden`）。`正当季` 和 `最后 N 天 / 今天最后一天 / 最好 a–b` 放同一行（`.kl`，剩余天数 ≤14 红，否则灰绿）；`4 天 · 人均 ¥2.5K–3.6K · 17°/5°` 一行（气温用 `°/°`，不再写“10 月白天 17℃，夜里 5℃”整句，网页换日期时 `.c` 同步换）。去掉“还剩 N 天”（正当季 + 最好区间已够）。图 88×116 → 76×100。每张卡平均高度约 217 → 约 140。
- **分页**：“现在去正好”首屏只露 8 张，“再看 12 条 · 还有 N 条”每次多露 12 张（原来一点就把 400 条全展开）；换天数 chip / 换日期会回到 8 张。“长途和自驾”同样每次 12 张。条目都在 DOM 里，没有删。
- **去掉的重复入口（用户：长途自驾不需要俩入口）**：①搜索框下面的 `.longbar` 长条；②天数 chip 末尾的“15 天以上 · N”链接 chip；③列表后面的黑色“全部目的地 · 按月份挑”长条（和频道第一格同一个 `/where/`）。保留频道那一格；`/where/` 页、页脚、sitemap、面包屑里的 /long/ 不动。
- **其他小事**：搜索框占位字缩短（原来在 390 宽被截断）；“跟片走”副标题缩成一行“纪录片和杂志”，三格等高；“长途和自驾”的 kicker 不再重复写天数。
- **判据**：`tests/home_ux_check.py`（playwright chromium，390×844 亮/暗 + 1280）把上面每个场景做成断言：首屏同时看到搜索 + 频道三格 + 替我挑那一行；搜索在替我挑之前；无 `.longbar`、`/long/` 在首页内容区只有 1 处；替我挑折叠、展开、选满出结果；首屏只露 8 张、再看多露一批；卡片无“翻开 ›”、无“月白天”整句、平均高 ≤150；日期条在 #now 里；老用户“我的行程 · N”在首屏；暗色无溢出、主要文字对比度 ≥4.5。`tests/data_checks.py` 第 22 项的“首页有 /long/ 链接”改成只看 `.chan2` 里那一格（页脚也有 /long/，只数 href 永远绿）。两个都做过反向注入（加回 longbar / 去掉频道那一格 / 搜索框挪后 / 加回翻开按钮），都红。
- 卡片气温按这条线默认出发月份写（`start_date(rr).month`）；“现在去正好”一栏按今天的月份，网页会按所选日期再换。
- 价格 `price_k` 能吃带小数的串（`¥8,900.0–18,500.0` → ¥8.9K–18.5K）。


### 首页栅格与节奏（2026-10-16 首页对齐检查定下的，样式在 `site.css` 末尾「首页栅格与节奏」一块，全部 `article.home` 内）

用户说“首页对齐、行间距有问题”，量出来的不一致：封面→搜索 14 / 搜索→频道 10 / 频道→挑三条 20 / 挑三条→分区 14（四种）；分区线紧贴标题（0px）；“长途和自驾”里“按目的地看全部自驾线路”那条黑条左右各多缩 20px 且字顶对齐；天数 chip 行在内容区中间被切（右边留 20px 空）；“我的行程”按钮图标和字隔 17px、左右内边距 12/24；360 宽频道格“按月份挑目的地”落一个“地”字、搜索框占位字被截；chip 高 36/40、按钮 36 都不到 44。

**栅格**：版心左右各 20px，所有区块的左缘（文字量文字、框量框）在同一条线 L，右缘在同一条线 R。唯一例外：横向滚动的行（天数 chip、挑三条每行的 chip）右端要铺到屏幕/版心边缘（`margin:0 -20px;padding:0 20px`），看得出“还能往右划”，不在内容区中间被切。外层已有 20px 边距的，里面不要再加（`.toc` 里的黑条出过这个事）。
**节奏**：竖向间距只用 8 / 12 / 16 / 24 / 32（`article.home` 上有变量 `--s1..--s5`），同一种关系永远同一个值：

| 关系 | 值 |
|---|---|
| 封面 → 搜索框 | 16 |
| 控件叠放（搜索→频道→挑三条、日期条→天数 chip→列表、列表→“再看”→“全部线路”条、挑三条展开后的行→行） | 8 |
| 分区线 → 标题；标题 → 内容 | 12 |
| 挑三条 → “现在去正好” | 24 |
| 区块 → 区块 | 32 |
| 卡片上下内边距 / 卡内行距 | 12 / 4 |

## 长线检索 /long/（2026-10-16，`build_site.long_page`）
- **为什么有**：105 天的边境线 5 月才出发，首页“现在去正好”只列当季线路，找不到。长线不管当不当季都在这一页。
- **入口（2 次点击内）**：首页频道导航第三格（**首页只留这一个**；2026-10-16 去掉了搜索框下的 `.longbar` 和天数 chip 末尾的链接 chip，重复入口）；`/where/` 标题下一行；页脚；sitemap、llms.txt。≥15 天的行程页 JSON-LD 面包屑里“走哪儿”换成“长线自驾”。N 都由 `LONG_TRIPS` 算，不写死。
- **数据来源**：`data/catalog/trips.json` 里 `days>=15` 且有行程页的全部线路（`LONG_TRIPS`，现 26 条）；季节取 `season.ok`（能去）和 `season.best`（最佳），按月份“沾边就算”（窗口里有一天落在这个月）；人均价 `price_k`；默认出发日 `start_date`；难度提示：任何一天最高点 ≥3000 米（`peak` 或 `elev`）= 上高原，≥1500 = 山路多，其余 = 平路；“沿海”按标题/每天标题里的沿海、海岸、环岛等词。
- **只有三个控件**（用户要少即是多）：搜索框、天数 chip（不限 / 15–19 / 20–29 / 30 天以上）、出发月份（不限 / 本月能出发 / 1–12 月，横向滚动）。地区、上高原、排序都不做成控件：地区、难度、沿海是卡片上的小标签，也能当搜索词（输入 西南、高原、沿海 都命中）；排序自动：选了月份，这个月“最佳”的在前，其次只是能去的；没选，按“最近能出发”（今天在能去的窗口里 = 0 天，其余按离窗口开始还有几天），同分天数长的在前。
- **卡片**：天数大字、标题、“A 出发，末晚 B”（或绕回 A）、最佳月份 + 人均价、标签（上高原/山路多/平路、地区、沿海）。点击进 `/trip/<id>/`。计数“找到 N 条”；无结果只有一个“清除条件”。
- **搜索**：关键词按空格拆开、全部命中；搜索文本 `data-q` = 标题、label、站点、每晚住的城市、地区、`N天`，所以“105”“105 天”“边境”“川藏”“海南”都能命中。状态写进 URL hash（`#m=5&d=c&q=…`），刷新、分享保留；用 `replaceState`，不堆历史。
- **全站搜索**：`/where/?q=`（首页搜索框也是提交到这里）在目的地卡片上方多一个“线路 · N 条”分组（短线长线都搜），数据是 `/assets/tidx.js`（建站时生成，第一次搜索才加载，约 470KB，gzip 后约 150KB）。
- **坑**：
  - 页面根类名不能叫 `.long`（行程页的 `.daynav.long`、`.hero-t.long` 已占用，脚本找到别的节点会报 null.children），用 `.lpg`。
  - 长线每天的 `city/navCity` 是前一晚住的地方，所以“终点”只能写“末晚在哪”，不是真终点。
  - 页面是静态的，月份“本月能出发”和排序由网页按用户今天的日期算；卡片上的默认出发日是建站那天算的，进行程页会重算。
  - 反向校验在 `tests/data_checks.py` 第 22 项：从 trips.json 出发，每条 days>=15 的线路必须在 /long/ 里；首页频道那一格（`.chan2`）、/where/ 要有链接，首页不许再有 `.longbar`；搜“105”命中 xb96a；没有悬空的 trip 链接；线路索引里要有 xb96a。

**入口（少即是多：不新增常驻按钮）**

[ 换成…                          ]   ← 新

## 触控目标 ≥44×44（2026-10-17）

量法不是量 `getBoundingClientRect`，而是 **elementFromPoint 实测**（含伪元素、被邻居盖住的都算进去）：`tests/ux_common.py::HIT`。要求：行程页的调整、日期格、出发时间“改”、恢复、去掉这一天、这天后面加一天、收进行程、按天看、返回/首页/分享、天数条、每人、要办的事、地图图标、预约入口、“再看两家”；首页的日期条（点“改”那个字也行）、我的行程、再看、替我挑、天数 chip、搜、频道、翻开；日历日期格和翻月键；提示条“撤销”。

- 小字按钮（`.adj`、`.dt`、`.ic`、`a.bkl`）**视觉不变**，点击区用 `:after{inset:-Npx}` 补；有真实高度的直接 44。
