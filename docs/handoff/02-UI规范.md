# 02 · UI 规范

总原则：**像一本杂志**，安静、留白、层次清楚；手机优先（iPhone 宽 390）；能少一样就少一样。

## 字体

| 用途 | 字体 | 说明 |
|---|---|---|
| 标题、片名、目的地名、分区名、导语 | `var(--serif)` = Noto Serif SC（只打包了 700、900 两个字重） | 网页字体按字切成两百多个小文件 |
| 正文、按钮、小字 | `var(--sans)` = Noto Sans SC，退回苹方 / 微软雅黑 | |

- 宋体的 `font-display` 是 **block**（等字到了再显示），**不要改回 swap**：swap 会让每次切页标题先显示系统字再跳成宋体（Jerry 投诉过“每次切换字体都会变一下”）
- 黑体保持 swap（和系统黑体长得像，看不出跳）

## 颜色和层次

变量：`--ink` 墨色（正文、标题）、`--sub` 灰（次要信息、标签）、`--line` 细线、`--red` 红、底色米色。

**红色只用在两类地方：**
1. 要点的：“改”、“要预约 ›”、“官网预约”、“携程订这家”、买票
2. 真要注意的提醒：快截止、晚了、限行

另外每天开头的大号日期数字（如“02”）保留红色，是每天唯一的视觉重点。
**其他一律墨色或灰色**：小标题（出发前、今晚住、懂一点、要办的事）、“01 02”序号、推荐 / 奢华档次、世界遗产 / 5A、国宝标签、镇馆之宝、纪录片片名、分区名。

三层层次（以纪录片页为例）：
1. 名字（吃的 / 国宝 / 景点）：墨色宋体粗
2. 集名、地点：灰色小字
3. 能去的行程链接：墨色细字，几条用“·”隔开，不带“›”，**不要下划线**（Jerry：“下划线真的很丑”）；频道切换标签也不画下划线，当前项靠加粗 + 墨色区分

## 对齐

- 页面左右边距统一 **20px**；所有文字的起点（小字、标题、导语、切换栏、分区标题）都在同一条线上
- 改样式后跑 `tests/webkit_align.py`，它量每段文字实际起点
- **教训**：不要复用通用类名（比如 `.kick`）去写某一页的样式——头图里同名的小字也会被改掉（出过一次 20px 错位）；新样式一律带页面前缀（`.where .kick`、`.chan .kick`）
- 外层已经有边距的元素，里面不要再加边距（走哪儿的切换栏出过 40px）

- 片子页的“第一季 第二季 …”和影像方志的省份跳转条（`.chan .jump`）和走哪儿的月份条同款：灰块、当前项墨色底，吸顶，滚动时跟着高亮（site.js 末尾）。不要再做成文字加下划线
- 插图：跟片走目录每行右侧一张 60×80 封面，片子页顶部一张横幅（高 210px，居中偏下裁切）；走哪儿每张卡左边一张 44×58 缩略图（取该目的地第一条线的海报）。插图一律用 `tools/posters/` 的画法（渐变 + 主角 + 颗粒），别用图标或照片
- 片子页每条先写名字，灰字地点，再一行“好在哪”（`why.json`），最后才是排进了哪几条线（只写线路名，**不写“第几天”**——Jerry：我更关心好在哪、为什么要去、为什么要吃）
- 每个条目左边一张小插图（`tools/motifs.py`：30 个平涂符号 × 10 套配色，按名字里的字选符号，配色按 hash，页面只带一次 ~14KB 符号表），右上角是 导航 / 点评 / 小红书 三个灰色小图标（`icons()`，吃的按“地点 + 菜名”搜，国宝按博物馆，地点按“省 + 名字”搜，国外用谷歌地图）
- 片名本身以“跟着”开头的，标题写“《跟着书本去旅行》里的地方”，别写成“跟着《跟着…》走”
- 跟片走目录（`.toc`）：灰色序号 01–11、宋体 22px 片名、一行小字“说明 · 拍过 N 处”

## 行程页

- 每天开头只留“出发（可改）”和“日落”两格（日出删了）
- 纪录片那一行最多写两样，多了写“等”，地方最多两个
- 时间轴一行：时间 · 名字 + 图标；第二行灰字：时长 · 门票 · 一句话；博物馆多一行“镇馆之宝”
- “懂一点”：段首一行小灰字写地方名，下面正文
- 目的地页列表的导航 / 点评 / 小红书图标是**灰色**（三十行一排红图标太花）

## 图标和外部入口

- 导航（高德）、点评、小红书：凡是有名字的景点、吃饭的地方、酒店、目的地页列表都要有；小红书按“城市 名字”搜
- 手机：只调 App（`amapuri://`、`dianping://`、`xhsdiscover://`、携程 `ctrip://wireless/h5`），没装 1.6 秒后提示
- YouTube 搜索入口（`a.ic.yt`）：排在小红书图标后面，纯网页链接 `youtube.com/results?search_query=<城市 地点> 旅行`，没有 App 调起，电脑和微信里也显示（不受 `.noapp` 隐藏）。
- 电脑、微信内置浏览器：不显示这些入口；微信里第一次打开提示“右上角在浏览器打开”

## 写字的规矩

- 短句、具体：写“从西安坐火车约 6 小时，或者坐飞机”，不写“交通便利”
- 纪录片写“推荐 / 早上吃 / 讲过 / 拍过”；多季的片子标“第几季”，只有一季或查不到多季的（`SINGLE_SEASON`：河西走廊、跟着书本去旅行、话说长江、新丝绸之路、丝绸之路、中国影像方志、两个杂志榜单）不写“第一季”
- 不知道的不写；拿不准的写成能核实的说法（例：远程航线写“要转一次机，路上总共约 X 小时”）
- 不重复：同一信息只出现一次（时间轴和“懂一点”不说同一句）
- 不要多余入口和链接（“下一天”就是被删的例子）

## 深色模式（2026-10-14）
- 跟系统（`prefers-color-scheme: dark`），没有手动开关。`site.css` 末尾的 `@media (prefers-color-scheme:dark){:root{…}}` 只换变量：`--bg --ink --sub --mute --red --card --green --blue --line --line2 --ink2 --lead --okbg --okfg --warnbg`。`--pink` 不换（它是封面上的浅色字）。
- **写新样式要用变量，别写死颜色**：正文/次要字用 `var(--ink)` `var(--ink2)` `var(--sub)`；浅底深字的徽标用 `--okbg/--okfg`、`--warnbg`；线用 `var(--line)`。写死 `#3d3f3a`、`rgba(28,29,26,…)` 这类浅色主题颜色，深色下会读不清。
- 压在图片或固定深色块（封面、头图、色块 `tile`）上的字用 `var(--onimg)`（恒为奶白），**不要用 `var(--bg)`**（深色下 `--bg` 是近黑）。
- 海报、封面是 `<img>` 的 SVG，深色下保持原样（浅色画面嵌在深色页面里）。走哪儿的地图是内联 SVG，底色也是浅的。
- 验证：浏览器里 `resize_window` 设 `colorScheme: dark`，用页面里算文字与有效背景对比度的脚本扫（低于 3.2 的列出），主要页面都扫过为空。

## 少即是多（2026-10-15，只改展示、不删功能）
- 行程页前言：概览列表（“N 天，怎么排”）和每天标题重复，用 CSS 藏起来（脚本仍在用它，不能删 DOM）；路线图默认折成一行“看路线图”（`.mapfold`，点一下展开）；“怎么去、怎么回”和“出发前”两块视觉上合成一块。第 1 天顶部约 860px（原约 1440px）。
- 国外页“出发前”里每页都重复的护照有效期/保险套话折成一行“出境通用须知 ›”（`li.gen details`），勾选框保留。
- 不做：把图标收进详情面板、按地区隐藏图标（用户要求图标都保留）；删分享/打印等功能（用户要求功能不减）。
- 规则：任一核心任务的点击步数不增加；新增字/控件要先说明删了哪个。
