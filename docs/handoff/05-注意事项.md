# 05 · 注意事项（都是真踩过的）

## 加线路

1. **月份从 0 开始**：`start: [2026, 8, 10]` 是 9 月 10 日。写成 12 会让建站直接报错退出；写偏一个月不报错但季节全错（蔚县打树花一度排到 1 月）。加完跑“月份越界”检查。
2. **编号会撞**：`yc2` 早被“盐城”占了，新写的“运城”就没加进去，检查时看到的其实是盐城那条。加线前先查 `id in itineraries or id in trips`。
3. **每天第一站必须写 `via`**：不写的话按国家默认城市算路程——纽约第一天算成从旧金山出发，79 小时。
4. **定点（`at`）别和长路程冲突**：前面三个半小时车程又定死 18:30，后面会排到半夜；凌晨定点（看日出、极光）同样要算总时长。检查“过 24 点”。
5. 新国家：`destinations.json` 加条目 → `geo/destinations.json` 加坐标和 12 个月气温 → `estimate_prices.py` 加机票住宿吃饭 → 新地区名加到 `build_catalog.py` 的 `REG` → 要转机的加到 `TRANSIT`（`build_site.py` 和 `site.js` 两处）。
6. 坐标按 `"城市|q"` 查；同一个景点在不同城市名下要各写一条。景点没坐标时，“加一天”的候选会用那天的落脚点（以前直接漏掉，白哈巴就是这样）。
7. 价格：游轮、包船这类估价不含船票，必须在 `prep` 第一条写明。

## “怎么去”的规则（`go_text`，`build_site.py` 和 `site.js` 各一份，改要两处一起改）

顺序：写明的出发点（第一天以“从X坐/去/到…”开头）→ 就在附近 → 秘鲁 / 要转机的国家 → 远程 → 出国 → 自驾 → 海南（坐飞机）→ 不通高铁（远的坐飞机、近的坐火车）→ 第一天就要包车大巴的小地方 → 高铁。
**新分支要放在一般分支前面**，否则永远轮不到（出过一次）。

## 页面和样式

- 不要复用通用类名写某页样式（`.kick` 事故）；外层有边距里面别再加（走哪儿 40px 事故）
- 宋体 `font-display: block`，别改回 swap
- 时间轴那句一句话，如果“懂一点”讲了同一个景点就不显示——统计“缺介绍”时要按 `SIGHT`/`DEEP` 字典查，不能按页面上显示了没有
- 网页脚本兼容微信老内核：别用 `?.` `??` `flatMap` `.at()`
- 加功能前先查网页里是不是已经有了（“按天看左右滑”就重复做过一次，滑一下跳两天）

## 加一天（`site.js` “加一天：自由活动”那一大段）

- 插在中间的天存 `after`（原来第几天）；放位置、“几天怎么排”序号、住几晚都要跟着重算
- 插在中间的天晚上回**那天住的地方**；只在最底下加的才按回程前最后一站

## 内容真实性

- 纪录片只收查得到出处的那一期；《跟着书本去旅行》目前只有 5 期有出处
- 歌词、诗词全文、文章大段不要抄进页面
- 拿不准的交通（直飞与否、通不通高铁）写成稳妥的说法

## 发布和环境

- 单条命令 300 秒上限：生成、建站、测试、发布分开跑
- Pages 构建失败要到线上核对，别看到“已推送”就当上线了
- 测试脚本输出前面可能混别的字，按 JSON 段落取结果
