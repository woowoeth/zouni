## 在 macOS 上跑（不是 Linux 容器）

- 没有 `timeout`，去掉即可；`base64` 没有 `-w0`
- **本机 Python 的 `urllib` 访问 HTTPS 会 `CERTIFICATE_VERIFY_FAILED`**：`compile_itineraries.py` 里在线地理编码会静默全失败，还会把失败缓存成 `None` + `#tried`（之后不再重试）。新线补坐标用 `curl` 查 Nominatim（`countrycodes=cn`，1.2 秒一个），**逐个核对命中位置**，不要关证书校验
- 发布：克隆 `woowoeth/zouni` 的 main（公开，不用令牌）→ 替换为新建的站（保留 `.git`/`.github`）→ `git diff --cached --name-status` 确认 0 个删除 → 提交 → 推送（令牌放环境变量 `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=http.extraheader GIT_CONFIG_VALUE_0="Authorization: Basic …"`，不写文件）。线上手绘封面 `assets/blob/*.svg` 在 source 分支里，本机项目缺这个目录会让 19 个页的头图退化，发布前先和线上逐文件对比

## 首页“替我挑三条”的矩阵检查（在浏览器里跑）

`tests/home_matrix_browser.js`：打开首页（本地 `python3 -m http.server` 起建好的站），把整个文件贴进浏览器控制台（或 `page.evaluate`）。37 个出发城市 × 周末/4–5 天/一周以上 × 三种同行 × 自驾也行/不开车 = 666 组，每组读前三条，断言：每组 3 条（不足时有说明）、同省 ≤2 条、“不开车”不含自驾、“带老人孩子”不含高原（最高天标 ≥2,500 米）和国外、每个城市周末距离中位数 ≤600 公里、4–5 天 ≤900 公里、周末有 >450 公里的推荐时页面有说明。返回 `{组数, 失败: [...]}`，失败为空才算过。
这个检查是 2026-10 因为“注释吞掉了后面的分支”才补的：4–5 天、一周以上的筛选曾经整个失效而没人发现。

### 改 `replan`（时间表核心）之前先存基线，改完逐项比
`replan()` 是全站时间表的核心，不是只有“顺路”会碰它。基线 = 改动前的站在固定时钟、固定天气下，把现有 webkit 脚本（“调整 / 去掉一天 / 加一天 / 下雨换室内 / 今天视图 / 分享 / 日历”相关的 15 个）加一个整页快照脚本跑一遍存下来：
```bash
python3 tests/nearby_baseline.py run build/site build/nearby_baseline          # 改动前：起本地服务（8765），逐个脚本跑，输出存成 <名字>.out（约 7 分钟）
# …改代码、重建站（build/site_new）…
python3 tests/nearby_baseline.py run build/site_new /tmp/nb_new
python3 tests/nearby_baseline.py compare build/nearby_baseline /tmp/nb_new      # 逐文件 diff，有差异退出码 1
python3 tests/nearby_baseline.py run build/site /tmp/nb_x --inject-diff         # 自检：故意让一份输出变，compare 必须红
```
- 这台机器没有 WebKit：`nearby_baseline.py` 在运行时把 `p.webkit` 指到 chromium，给每个 context 注入固定的“现在”（2026-10-16 14:20 +08:00）和固定的天气接口响应，**不改原脚本**。
- `tests/nearby_dom_snapshot.py`：补 webkit 脚本只打印前几行的缺口——整页每一行的 时间 / 名字 / 第二行 / 隐藏 / 关键 data 属性 / 导航链接 / 页头摘要 / 复制行程 / 日历 / 分享链接 / 今天视图，在 原样、改出发时间、多待少待、去掉一站、组合+晚点、去掉一天、加一天、下雨换室内、全叠加 九种状态下各存一份，xa3 gqhx10 xl9a tk4 par5 nj3 slgt8 bkk3 八条线。
- 有 4 个老脚本（`webkit_adjust_share_weather` 的放慢节奏、`webkit_rain_monday_allstart` 的整趟改出发、`webkit_map_addday`、`webkit_nextday`）点的按钮早被删了，**在改动前的站上就超时**；比对时比的是“怎么超时的”，不是输出。它们原来想测的（分享链接带修改、下雨换、加一天）由 `nearby_dom_snapshot.py` 覆盖。
