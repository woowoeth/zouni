# 设计：给每条线路一张“路书地图”（总览图 + 每天小图 + 一键带入导航）

> 2026-10-17 调研与设计。只读代码、只写本文档，没有改任何代码或数据、没有跑构建（读的是 `build/site` 已有的站和 `build/routes.js`）。
> 需求来源：用户给了一个自驾路书产品的做法——大图看全局（红色主线、绿色小众支线、景点、免费观景台、停车区、吃住、高速出口、导航名称）、每天一张小图、文字讲到哪里旁边就能对着找、每天一键带入导航软件。问：能不能给每条线路做出这样的完整地图？
> 用户之前明确的约束：不做打印、少即是多（少步骤，不是少功能）、核心是内容和线路设计、站点不显示任何来源/视频字样。

## 0 · 先说结论（executive memo）

**现状**：线路页已经有一张“路线示意图”（Python 在建站时画成内联 SVG，`tools/mapdraw.py`）：真实省界/国界做底、红色折线、每天第一站一个圆章、放得下的景点名。默认折在一行“看路线图”里，点开后点图再放大（只是把 SVG 放大到 220vw 横向拖动）。它**不能点**、**不和时间表联动**、**没有每天的图**、**没有吃住、没有停车/观景台/高速出口**，105 天那条线只有一个很小的 SVG（77KB）把 105 个圆章压在一起。
**麻烦**：用户想要的是“照着文字在图上找得到”。这件事需要三样东西：①图上的点和页面行有编号联动；②每天一张小图；③能带入导航。第 1、2 项靠我们**已有的数据**就能做（每个景点/吃饭行已带 `data-ll` 坐标，每天已带 `data-sp`/`data-ep`），第 3 项受高德 URI 限制（一次只能 1 个途经点）。**真正拿不到的是“免费观景台、停车区”**：OpenStreetMap 里这类点在中国绝大多数没有名字，更没有“是否免费”（5 条自驾线实测，见 §5）。
**要决定什么**：地图做成“不依赖底图服务的自画示意图”（推荐）还是接真实地图瓦片；沿途停车/观景台/高速出口要不要做、做到什么质量才敢标。
**做法**（一句话）：**浏览器端按页面里已有的坐标现画一张可点、可缩放、与时间表联动的示意图（新文件，按需加载），不依赖任何地图服务；每天一张小图默认折叠、打开后贴在这一天的顶部随滚动高亮当前站；每天一个“导航”入口（国内高德分段、国外谷歌最多 3 个途经点）；停车/观景台/高速出口放到第三期，只标有名字、人工核过的点。**

### 一页版：推荐 vs 放弃

| 问题 | 推荐 | 差一点选中、放弃的 |
|---|---|---|
| 底图 | **自画示意图**：已有省界/国界 + 路线 + 编号点，不联网也能看 | OSM 瓦片（政策限制、国内慢且不稳）；MapLibre + 自托管矢量瓦片（体积和工具链不允许）；高德/百度 JS（要 Key、要审图号） |
| 每天小图 | 默认折叠，点开后**吸顶在当天里**，滚到哪行高亮哪个点；由 JS 在点开时才画，页面 HTML 零增长 | 每天常显（首屏 +200px/天，页面体积翻倍）；每天一张 Python 预渲染 SVG（见 §3） |
| 总览图 | 保留现有静态 SVG 作为首屏和无 JS 兜底，**点开换成新的可交互版本** | 一次性删掉静态 SVG（每页省 33KB，但要改一批旧测试和快照，放第二轮再看数据） |
| 绿色小众支线 | 用“顺路”候选分片的点，**浅灰空心点，默认关，一个开关** | 另做一套“支线”数据（没有数据来源，会编造） |
| 停车/观景台/高速出口 | 第三期，**人工白名单**，只标有名字且核对过的 | 全量灌 OSM（见 §5，大多无名、含私人停车场、含错标） |
| 一键导航 | 国内高德“整天拆成最多 N 段，每段一次只带 1 个途经点”；国外谷歌 ≤3 个途经点 | 声称“整天一键全程”（高德做不到） |

### 1.2 每站有哪些可用字段

**源数据**（`data/itineraries.json`，见 03 号文档）：`stops[]` 有 `name / q / type(sight|park|street|museum|fun|night|food|town|temple|beach…) / dur / via / at`；天有 `city / stay(片区名) / lunch / dinner`。
**编译后** `build/routes.js`（`compile_itineraries.py`）每天 `rows[]`：`dep`（`to / how`）、`see|fun`（`name / d / poi / dp / at`）、`eat`（`slot / dish / place / poi / dp`）。**没有 `stay` 行、没有行级 type**；天级有 `stayName`、`stay[]`（酒店三档，**没有坐标**）、`lat/lng`（当天城市中心）、`driveMin`。
**页面上已带的 `data-*`**（`np_row_attrs` L15229、`np_dep_attrs`、L16169）：`li.r[data-ll="lat,lng"]`（`see/fun/eat` 且 `poi` 解析出坐标且不是“沿途”）、`data-dm`（停留分钟）、`data-ty`（2 字类型码，只有 see/fun）、`data-pid`；`section.day[data-sp, data-ep, data-lm, data-pc, data-drv]`（这天从哪出发/晚上回哪）；`dep` 行 `data-mode/min/km`。
**实测（`build/site/trip`，1600 页）**：每页带 `data-ll` 的行中位数 6、最多 200（`xb96a`，105 天）；31 页 ≥15 天；149 页没有现成的图。全库 11942 个 see 行、9962 个 eat 行、203 个 fun 行。
**能直接用作图的**：景点点（`data-ll`）、吃饭点（`data-ll`，但 eat 的 `poi` 是“地点/街”而不是店，位置是片区级）、住宿点（**只有 `data-ep` 一个片区点，不是酒店**：`stay_fix` 把片区名 geocode，离城市中心 >60 km 就退回城市中心，L16163–16167）、博物馆/寺/山水（`data-ty` 的类型码）。
**图上不能假装有的**：酒店位置（只能标“住 · 某片区”，点是近似的）、停车区、观景台、高速出口、“小众”标记（`niche.json` 只在目的地页，线路行里没有字段）。
**导航名 q**：`data-ll` 是已解析的 WGS84 坐标，页面上并没有保留 q；导航图标的 `aria-label` 带名字。“图上标导航名称”可以直接用站名（`SIGHT` 命名即导航名）。

## 2 · 总览图设计

### 2.1 目标样子（手机 390 宽）

```
┌──────────────────────────────────────┐
│ 路线图                           关上 │   ← 全屏层（沿用现在的 .hmap-zoom，加 pk-open）
│ ┌──────────────────────────────────┐ │
│ │      [ 示意图，可拖、可双指缩放 ]  │ │   主线：红色粗线；选中的那一天加粗，其余天变淡
│ │   ①成都 ──②雅安 ──…              │ │   每天第一站一个红圆章（沿用）；当天站点：小点+序号
│ │        ○ 灰色空心点 = 顺路可去     │ │   
│ └──────────────────────────────────┘ │
│ 第 1 天 ‹  成都 · 都江堰  ›  ← 底部这天的名字（点站点/切天时变）│
│ [ 顺路可去 ]  ← 唯一的开关（默认关）                          │
└──────────────────────────────────────┘
```

**图例要少**：只有三种东西需要解释，且直接画在图上不另设图例块——红线=行程；红圆章=第几天；灰色空心点=顺路可去（只在开关打开时出现，开关本身就是图例）。站点类型不靠颜色（红色规矩：红色只给要点的和提醒），靠**形状/字**：景点实心小点 ●、吃饭 ◇、博物馆 ■、住宿 ▲（带“约”：片区级）；其他不画。不放比例尺以外的东西。

### 2.2 点什么、发生什么（联动）

| 动作 | 结果 |
|---|---|
| 点图上一个站点 | 底部条显示“第 N 天 · ③ 西安城墙”+ 两个动作：**“在行程里看”**（关掉全屏层、滚到页面里对应行并高亮 1.6 秒，沿用 np 加站后的高亮）、**“导航”**（该站高德/谷歌链接，沿用 `a.ic.map` 同一份 href 和 `data-ios/and`） |
| 点页面里某一行的小编号 | 打开地图层，聚焦这天，闪烁对应点（编号只在地图打开期间显示，见 §8） |
| 点红圆章（几号） | 聚焦这一天，其他天变淡，底部条切到这天的标题 |
| 双指/＋－ | 真缩放（改 viewBox），字号不跟着变大；层级见 §2.4 |
| 点图外空白 | 取消选中 |

**与时间表联动的实现**：全部读页面 DOM（`.day[id=dN]` → `.tl .r[data-ll]`），不另存数据。因此“去掉这一站、顺路加一站、换一站、加一天、去掉一天、下雨换室内”后图自动是对的（和 `replan` 同一套状态，不引入第二套）。这一点是推荐“JS 现画”而不是“Python 预渲染”的主要理由。

### 2.3 数据模型（新：`routemap` 模型，纯函数，由 DOM 算出）

```
model = { app: 'amap'|'google', days: [ { i, title, sp:[lat,lng]|null, ep:[lat,lng]|null,
          pts: [ { n: 1..k, kind: 'sg'|'eat'|'mu'|…, name, ll:[lat,lng], rowId } ] } ] }
```
- 编号 `n`：**每天从 1 开始，按页面里时间顺序，给每个有坐标的 see/fun/eat 行编号**（吃饭也编号，才能和文字一一对应）。
- 住：`ep` 画一个 ▲，不编号。
- 没坐标的行：不画、不编号（§8 空状态）。
- `kind` 来自 `data-ty`（see/fun）和 `li.r.eat`（吃）；`data-ty` 缺失当景点。

### 2.4 长线怎么不糊（105 天、200 个点）

现有 `xb96a` 的图是一条 105 天的折线压成 77KB 的 SVG，点和名字全糊。设计成**三级缩放**，由 viewBox 缩放比自动切换，不加控件：

| 缩放 | 画什么 | 例 |
|---|---|---|
| L0（全貌，初始） | 一条细红线 + **每 7 天（或每个 `day.city` 换省）一个大圆章**“1 · 8 · 15…”；省界；不画站点和名字 | 105 天 → 15 个章 |
| L1（约 2×，一段） | 每天一个小圆章 + 站点小点（无名字）；非当前段的天变淡 | |
| L2（约 4×+） | 站点编号 + 名字（只显示当前视窗内的，沿用 `render` 的 8 候选位避让） | |
- 底部条是“段”选择：横向滚动一行 chip（`1–7 天` `8–14 天` …，≤15 个，**不是 105 个**），点一个 → 缩放到这一段。≤14 天的线路没有这一行（整条就是一段，不加控件）。
- 段的划分：连续 7 天；`days>=15` 才启用（`is_long`，build_site L29，已存在）。备选：按“换省份”分段更符合人的心理，但省份要从坐标反查，边界处会出现 1 天的小段，第一版不做（§10）。
- **渲染成本控制**：只渲染视窗内的点；L0 不渲染站点（200 个 DOM 节点在手机上其实不算大，但文字避让是 O(n²)，限制每次只对视窗内 ≤40 个名字做避让）。

### 2.5 “顺路”候选作为浅色备选点（绿色小众支线的替代）

- 数据：已有的候选分片 `assets/np/<纬格>_<经格>.js`（3° 格，6873 条，字段 `n 名字 / c 城市 / a,o 坐标 / t 类型 / d 停留 / s 一句话 / q / ap(高海拔) / p(被几条线用过)`；`design-nearby-stops.md` §2）。
- 显示：开关“顺路可去”打开后，按视窗包围盒取分片（沿用 `np_model.js` 的取片规则，通常 1–2 片，每片 ≤25KB），画**灰色空心点**，≥L2 才显示名字；**只显示离本线任一站 ≤35 公里**（和 np 同口径）、本线没有的。
- 点它：底部条显示名字 + 一句话 + 一个动作“在 第 N 天 后面加这个”→ 走**现有** np 的加站流程（不另造）。
- 不做“小众/热门”两种颜色：池里没有可信的“小众”字段（`niche.json` 只是目的地页的 530 条，不在线路行里，且 `status` 多为“出发前查”）。**宁可只叫“顺路可去”，不编“小众”。**
- 国外线、偏远线候选常为空（`design-nearby-stops` §2.5：国外 52% 的线 0 个）：开关置灰，不画。

## 3 · 每天小图

### 3.1 位置和默认状态（推荐：默认折叠，打开后吸顶）

- **位置**：每天头部（出发/日落两格）下面，和“导航”并排一行两个小按钮：`本日地图 ›`、`导航 ›`（§6）。**只有这天 ≥2 个有坐标的点时才出现**。
- **默认折叠，理由**：①首屏第 1 天已经被压到约 860px（02 号文档“少即是多”），常显一张 200px 的图会再顶下去，用户明确要少；②每页平均 6 天、105 天那条 105 天，常显=页面体积和 DOM 都翻倍（见下“性能”）；③读文字的人大多先读，“找不到”才看图，折叠的一行按钮已经足够找。
- **打开后**：图吸顶（`position:sticky; top:0`，只在这一天的 `section.day` 内），高度 ≈ 200px（390×200），用户往下滚读时间表，**图上高亮“视口中间那一行”对应的点**（`IntersectionObserver` 观察 `.tl .r`），点图上的点→滚到对应行。这回答了用户那句“文字讲到哪里，旁边就能对着找”。
- **已经打开了就记住**：`sessionStorage` 记“这条线路的地图是开的”，下一天默认展开（不是全部，只是用户习惯；否则每天都点一次）。**不进 localStorage、不进分享链接**。
- 收起：再点一次 `本日地图 ‹`；翻到下一天时上一天的图随 sticky 自然顶掉，不会叠两张。

### 3.2 和总览图的关系

同一个渲染模块（`ZRouteMap.draw(el, model, {day: i, mini: true})`），同一份模型。区别：小图只画这一天（路线、编号点、住▲、`sp` 起点“出发”）、不画省界（尺度太小，省界只是一条直线，白白占体积），画一个比例尺 + 每段车程分钟（取自 `dep` 行 `data-min`）。小图右上角一个“看全图”→ 打开总览并聚焦这天。

### 3.3 小图的底（没有底图服务时）

- **不画道路**。<60 公里的尺度画省界没有意义。底是纯色（和页面卡片同色）+ 路线 + 点 + 比例尺。读者靠的是**相对位置和顺序**，真地图靠每个点的“导航/地图上看”。图下一行灰字“示意图，位置是相对的；点站点用地图 App 看真实路线”（沿用断网说明的措辞风格）。
- 如果某天所有点都在 300 米内（同一园区里），不出图、不出按钮。

### 3.4 性能与体积（1600 条线路）

| 方案 | 每页增量（中位 / 最大） | 1600 页总增量 | 首屏 |
|---|---|---|---|
| **推荐：JS 点开才画，HTML 里只加两个按钮** | ≈ 2×60B×天数 → 6 天约 0.7KB；105 天约 13KB | ≈ 1.5MB 原始（gzip 后很小） | 无影响（脚本懒加载） |
| 每天预渲染 SVG 内联 | 每天 ≈ 4–8KB（含点和字） → 6 天 ≈ 30–50KB；105 天 ≈ 600KB+（页面已 2.1MB） | ≈ 60MB | 中位页 125KB→170KB，Slow 3G 判据（`tests/slow3g_check.py`，HTML 体积/首次绘制）要重设 |
- 新文件 `assets/routemap.js`（估计 12–20KB 原始，ES5，未实测）按需 `<script>` 注入（和 `qr.js`、`np_model.js` 同做法），**不进 site.js**（site.js 已 239KB，06 号文档待办里写了“按需加载”）。`basemap.js` 118KB 只有打开**总览**才取（小图不需要），“收进行程”时已会一并存（L270），断网照用。
- `sw.js` 不用改：`.js` 本来就走“先网络、断网用缓存”（04 号文档）；`data_checks` 28a 守着这条。
- 新文件的版本指纹进 `ASSET_V`（和 `np_model.js` 同法）。

## 4 · 底图与离线

### 4.1 选项对比

|---|---|---|---|---|---|

| D 高德/百度/天地图 JS 底图 | **要 Key**，高德个人额度有限 | 是 | 否 | 要审图号和备案、显示规则；**用户要求不得引入需要 API Key 的服务** | 放弃 |
| E MapTiler/Mapbox/Stadia 等 | 要 Key，有免费额度 | 慢 | 否 | 同上 | 放弃 |
| F Google 静态图 | 要 Key，收费 | 否 | 否 | 同上 | 放弃 |

### 4.2 推荐方案

**国内线、国外线都用 A。** 国外线现在就是同一套 `ne50` 国界；<2 个国家的小尺度同样不画底。
**增强项（第二期可选，不是第一期）**：加入 Natural Earth 湖泊/河流（公共领域）做**水系**，让 100–500 公里尺度的图能认出“青海湖、长江”（估计 +60–150KB，未实测，必须先量再定，且作为单独文件按需加载，不进 `basemap.js` 以免拖慢走哪儿的地图）。不做道路（没有可用的离线、小体积、合规的道路数据源）。
**离线**：总览图的底图在“收进行程”时已存（`basemap.js`，L270 `offlineExtras`），`routemap.js` 要加进同一个列表；小图无底图，断网照画。断网时：沿用 `mapOffNote`（“断网中：路线图是示意图，能看；点地图、导航图标要联网才能打开地图 App。”），“顺路可去”开关断网且分片没存时置灰并写“没网”（沿用 np 的“没网，稍后再试”文案）。`mapOffNote` 现在只对 `figure.hmap` 挂说明，新全屏层要在自己的条里也挂一份（否则断网时全屏层里没说明）。

### 4.3 合规与稳定性风险（我不是律师，列出来给你判断）

1. **中国地图画法**：公开地图服务有“审图号”要求。我们画的是“示意图”，但用了真实省界、国界。底图里：台湾、港澳是否以省级单位表示、南海诸岛是否有、藏南/阿克赛钦等边界线怎么画，需要有人核对一次；`ne50.json` 国界来自 Natural Earth（它对争议地区的画法**不一定**符合中国要求）。**已知风险，不是本设计引入的**（`hand_map` 现在就这么画），但路书图用得更多、更容易被截图传播，所以建议第一期顺手核一次，并把核查结果写进 05 号文档。
2. **OSM 数据（第三期）**：ODbL 许可，使用要署名“© OpenStreetMap contributors”，在图/页面脚注可见；站点原有“不显示来源/视频字样”的约束针对的是视频来源，不冲突，但要明确是这一处例外。
3. **瓦片服务条款**（只对选项 B 有意义）：见上表；不作为默认。
4. **稳定性**：A 方案零外部依赖；唯一联网动作是用户点“导航”后由手机 App 完成。

## 5 · 自驾线的额外信息：停车区、免费观景台、高速出口

### 5.1 来源与方法

OpenStreetMap + Overpass API（`overpass-api.de`，公共实例，只用于调研；**不进建站流程**，建站不联网）。
查询：沿线走廊 `around:R(各站点依次连成折线)`，R=3000 m（川西小环线因第一次请求 502 超限，改为 R=2000 m 重试成功，下表标注）。标签：`tourism=viewpoint`、`amenity=parking`、`highway=motorway_junction`、`highway=services|rest_area`、`amenity=fuel`、`highway=mountain_pass | mountain_pass=yes`。**一次一个请求、间隔 ≥12 秒**；遇 502（服务器满载）等 20 秒重试。原始结果在 `/private/tmp/claude-503/…/scratchpad/ovp/*.json`（不在仓库里，是调研用的临时文件）。
**注意方法局限**：走廊是“相邻两站直线”，山区绕路时会漏掉真实道路旁的点、也会多拉进直线附近但不在路上的点（如城市里的点）。

### 5.3 质量判断

- **国内：观景台和停车几乎没有名字**（hx7v 27 个观景台只有 3 个有名；ylx8 的 81 个停车一个都没名字；hx7v 的 27 个观景台里有 17 个是张掖丹霞一带的同一簇无名点，实际是同一处景区里的几个台）。**“是否免费”基本没数据**（`fee` 标签 hx7v 只有 2/101）。所以**“免费观景台、免费停车区”这一类信息不能从 OSM 批量得到，也不能靠推断**。
- **高速出口（`motorway_junction`）国内质量最好**：名字就是路牌上的互通名，hx7v 32 个有 25 个有名（武威南、张掖西、嘉峪关……）；`ref`（出口编号）几乎没有，**所以“图上标出口名字”可以，“标 G30 第 X 号出口”不行**。一个互通常有 2–4 个 node（上下行/匝道），需要合并（同名 500 米内合一）。

- **做，但放第三期，且只做三类**：①**高速互通/出口名**（国内自驾线）；②**服务区**（有名、非私人）；③**有名字的观景台/停车场，且离线路里已有的一个站 ≤500 米**（即“这一站旁边有个停车场叫 X”，挂在已有站上做备注，不单独当景点）。**不做“免费”标记**——没有可靠数据；若人工核实过（官网/景区公告）再写进行内小字，写“免费”之前必须有核验记录。
- 范围：现有 `drive` 线路 53 条、403 天（国外自驾 8 条）→ 约 53 个 Overpass 请求（每个间隔 ≥12 秒，≈15–20 分钟纯等待，加重试和审阅）。
- **数据形态**（新增，不进 `itineraries.json`）：`data/route_extras/<rid>.json`
  `[{"k":"exit|service|park|view","n":"武威南","a":37.8138,"o":102.6918,"day":2,"after":"乌鞘岭","osm":"node/123456","chk":"2026-10-xx 人工","note":""}]`
  由 `tools/fetch_route_extras.py`（Overpass，一次一个请求，缓存原始响应到 `build/overpass/`，**只产出候选清单**）→ 人工/审阅 agent 逐条标 `chk` → 入库。
- **反向校验（“不得标出不存在或不开放的点”）作为会红的闸**（`tests/data_checks.py` 新增一项，必须反向注入验过）：①每条必须有 `n` 名字、`osm` id、`chk`；②离**该天**线路任一站 ≤5 公里（防止错天）；③`access` ∈ {private, customers, permit} 一律不进；④同类同名 500 米内去重；⑤名字不含黑名单词（Lounge、Business、售票处、办公、员工）；⑥“免费”字样只允许在 `chk` 非空且 `note` 含出处时出现；⑦**从产物出发**：页面里每个路书点都能在 `route_extras` 里找到（防止数据删了页面还留着）。反向注入：塞入 Lounge、塞入 `access=private`、塞入距离 30 公里的点、塞入无 `chk` 的点，四者都必须红。
- 页面呈现：总览图和当天小图里画成**小方块/小字符号**（出口 ⇥、服务区 ▭、停车 P、观景 ◎），**默认只在小图里、且 ≥L2 才显示**，总览不画（避免“糊成一团”）；每天的文字里不加新的行（06 号文档“一直想做没做：每天加一行实用提示”，可以后续一起做，不属于本期）。

### 6.2 推荐的“每天导航”入口

位置：每天头部和“本日地图”并排的小按钮 `导航 ›`（小档 28px 视觉、触达补到 44，02/ui-spec 三档里的“行内动作”）。
行为（只在 iOS/安卓、非微信里；微信/电脑里和现有图标一样隐藏，沿用 `.noapp`）：
- **国内自驾/包车日**：把当天按顺序的点（`sp` → 各站 → `ep`）**拆成若干段，每段最多“起点 + 1 个途经点 + 终点”**，弹一个小选择层列出各段：“① 出发 → 西安城墙 → 钟楼”“② 钟楼 → 回民街 → 住处”。点哪段，用 `zOpen(amapuri://route/plan/…)` 或 `uri.amap.com/navigation?from=&via=&to=&mode=car&callnative=1` 调起。**不承诺“一键全程”。**
- **国外线**：一次调谷歌，`waypoints` 取当天中间站，**最多 3 个**（超出则按“最远绕路优先”留 3 个，其余在文案里提示“一天 N 个点，已带入最主要的 3 个”）；每个点用 `lat,lng`；URL 长度断言 <2048。
- **纯步行/地铁日**（`data-lm=city` 且没有开车）：不显示这个按钮（高德多点只对驾车有效）。
- 保留现有“每段两站导航”不动。

### 6.3 坑（来自读现有代码和文档）

1. **坐标系**：站点内部全是 WGS84（`pois.json`），高德要 GCJ-02。`wgs2gcj` 在 Python（L6892）、JS（`npGcj`，L566，带中国范围判断）各一份，**新代码必须复用 `npGcj`，不要再写第三份**，并加一条测试：同一点在页面里原有导航 href 里的 GCJ 坐标与新入口一致（防止偏 300–500 米）。
2. 国内线里夹国外点（口岸、澳门/香港/台湾）：线路的 `navApp` 是整条线一个值（`amap` 1198 条、`google` 402 条），港澳台线路走哪一个、边境线跨境日怎么办，要逐条看；`xb96a`（边境线）全程国内走高德。
3. **点名**：`from/to/via` 的 name 参数要 `encodeURIComponent`；名字含 `&` `#` 会截断（现有代码已处理，复用 `npEnc`）。
4. 微信内置浏览器不允许 scheme（站点已有“右上角在浏览器打开”提示），电脑端也不要显示按钮。
5. 断网：沿用 L10 的“地图需要联网”拦截（选择器要加新按钮的类名，否则断网点了会白屏）。
6. **没有现成的实现可以直接拿**：在现有仓库里已有“相邻两站”的实现（L566–583，L7106），多点是新写；开源里有各类“唤起高德/百度”的 H5 封装，没有一个提供“按天自动拆段”，不值得引入依赖。

## 7 · 分享与导出

### 7.1 把总览图/每天图保存成图片

- 做法：`SVG 字符串 → Blob/dataURL → Image → canvas.drawImage → toDataURL('image/png')`，用现有 `shotTrip` 同一套 canvas 画布与二维码（L438–465）。**SVG 必须自包含**（不引用外部图/字体，否则 canvas 被污染、`toDataURL` 抛安全错误；不用 `foreignObject`，Safari 不稳）。中文字体不能内嵌，SVG 转图后用系统字体（苹方/思源），和页面略有差别，可接受。
- 入口：**不新增按钮**。分享层（`.share` → `.pk`，L279–283）现有四项“发链接/复制整条行程/生成分享图/打印”。改法：“生成分享图”点开后图上方加一个二选一的小分段 `封面 · 路线图`（默认封面，原有行为不变；选路线图则把总览图画在 1080 宽、下面接“第 1 天…第 N 天”的标题列表，右下角同一个二维码，**只放线路网址**）。每天的图：小图工具条里一个“存这天的图”，直接生成 1080×1080 的单日图（同一个二维码、同一个页脚）。
- 二维码：沿用 `qrcode(0,'M')` 写 `location.origin + location.pathname`，不带修改状态（原有注释：带上去二维码太密，手机扫不出）。

### 7.2 文字版路书（复制行程）带上“看图对应编号”

`tripText()`（L288）现在每行输出 `时间 名字 …`。改为：这天有地图（≥2 个有坐标点）时，每个有坐标的 see/fun/eat 行前加圆圈编号 `①②③…⑳`，>20 用 `(21)`；没有坐标的行不加。分享图的路线图上用**同一套编号**。
- **这会改变所有线路的“复制行程”输出**，`nearby_baseline` 里“复制行程”一项会整批变（有意差异，需要写进汇报并更新基线，见 §9）。备选：只在“复制整条行程”之外再加一个“复制行程（带图号）”——多一个入口，违背“少即是多”，所以放弃。
- 国外/没有地图的线路：行为不变。

### 10.2 差一点选中的方案，以及为什么放弃

1. **OSM 官方瓦片做底图**：对用户最“像”那个产品；放弃是因为政策（署名、不得重度使用、不得预取）、国内访问未验证、无法离线、每次打开地图都要打外部服务。保留为“用户点‘看街道’时按需加载”的备选，第一期不做。
2. **自托管 PMTiles + MapLibre**：放弃——整国数据 GB 级超过 GitHub Pages 限额，且没有 node 工具链，JS 体积也与“站点体积控制”冲突。
3. **每天一张 Python 预渲染 SVG**：简单、无 JS；放弃——页面体积翻倍、Slow 3G 红灯、而且“去掉一站/顺路加一站”后图就是错的（现有 `redrawMap` 只重画圆章的教训）。
4. **每天小图常显**：对“对着找”最直接；放弃——首屏被顶下去、用户要少，改成吸顶+折叠。
5. **整天一键带入多点导航**：用户想要；放弃“承诺”——高德只给 1 个途经点，谷歌手机上最多 3 个；改成分段。

**差一点选中的方案（保留，防止以后忘了为什么没选）**

- *面板手势用 `touch-action: pan-y` + 原生滚动处理一切*：拉满时列表滚到顶继续下拉没法接力（浏览器已经接管了这次手势），只能用 touch 事件 + `preventDefault`。
- *点站点后页面滚到那一行（旧做法）*：整屏里页面看不见，滚了也没用，而且会让点地图和点列表“对不上、跳来跳去”（用户抱怨的联动）。改成**关闭后**才滚到选中的那一站。

## 决策 D31：去掉地图下面的行程列表，行程只有页面时间轴一份（2026-10-18）

**经过**：用户先说“地图下面的行程和我现在的行程是分离的，能整合到一起吗”。我（第一版）理解成“把完整时间轴搬进地图底部面板”，做了 `ZD`（当天模型）+ 面板里的完整行（时间 / 站间车程 / 吃饭 / 住 / 调整 / 撤销 / 改出发时间）+ 点行飞到站 + 点车程行加粗该段，53 条判据全绿。用户随后纠正：“**不是说过了吗，地图下面的行程去掉，用页面里每天的就够了**”。真正的意思是：**删掉**地图下面的列表，不是把它做全。

**决定**
1. 整屏地图保留：左上 ×、右侧控件列（回到视野 / + / − / 存图 / i）、手势、flyTo、示意图兜底、进度条、提速。**删除**：三档底部面板、面板里的站点列表、拖动 / 吸附 / 惯性 / 列表接力滚动、面板高度联动的地图容器增长（growMap）。

## 决策 D32：地图细节打磨——先找标点错位的根因，再逐条修（2026-10-19）

**起因**：用户用手机 390 宽走了一遍线上 /trip/xa3/，说“地图模块还是有很多细节不爽”，随后又加一条最高优先的：**放大、缩小以后站点标点（方块 / 住 / 灰点）的位置是错的，没贴在真实坐标上**。

**根因（已修）**：每天的颜色类叫 `rm-c0 / rm-c1 / rm-c2`，站点卡片里的“一句话”类也叫 `rm-c1`（`.rm .rm-c1{margin:0;…}`）。同一个类名两个用途，卡片那条规则把方块的 `margin:-22px 0 0 -22px`（把 44px 的方块中心放在坐标上）冲成 0，于是**第 2、5、8… 天（颜色类 rm-c1）的方块和“住”整体偏到真实坐标的右下 22px**。缩小时 22px 只是几百米看不出，放大后一眼错位；第 1、3 天不受影响，所以我们自己的测试（都只开第 1 天）一直没红。排查过的、**不是**根因的：DOM 叠层只在 moveend 才更新（实测每帧 `move` 都更新，缩放动画 41 帧最大误差 0.5px）、锚点取左上角、示意图 / 街道图投影不一致、pixelRatio（DPR 1 / 3 都对）、容器 resize、合并章用平均位置（用的是第一站的真坐标）。判据：用 maplibre 自己的 GeoJSON 圆点图层（渲染器自己的投影）读 canvas 像素，和方块中心比，≤2px。
**第二个同类问题**：街道底图放大到 z17 或拖得很远以后失败回退示意图，示意图的摄像机被 `clampC` 夹回（最多比初始放大 4 级、范围只有站点包围盒外 60%），站点位置瞬间跳到别处。改成回退前 `admit()` 把示意图范围放宽到当前摄像机。
**改法**：颜色类改名 `rm-dk0-2`（色）/ `rm-dt0-2`（深浅），起步壳（site.js）同步；`tests/map_anchor_check.py` A1 从样式表出发查“颜色类只许设 --dc”，A2–A8 查位置。**没有**改成 maplibregl.Marker：位置本来就对，换实现不解决根因，还要重做深色滤镜 / 示意图兜底 / 命中测试（D22 的理由仍在）。
