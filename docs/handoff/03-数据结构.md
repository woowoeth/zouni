# 03 · 数据结构

## 1. 行程 `data/itineraries.json`

```jsonc
{ "note": "...", "itineraries": {
  "slgt8": {                       // 编号：全站唯一，加线前先查有没有被占（见 05）
    "dest": "gansu",               // 目的地 id，对应 destinations.json
    "city": "西安",                 // 第一天所在城市
    "label": "丝绸之路 8 天",        // 列表里显示的名字（以“N 天”结尾）
    "title": "八天，坐火车走丝绸之路", // 行程页大标题
    "kicker": "长线 · 8 天",
    "start": [2026, 8, 10],        // 默认出发日 [年, 月, 日]，**月份从 0 开始**（8 = 9 月）
    "drive": true,                 // 可选：自驾线
    "prep": ["…", "…"],            // 出发前提醒（每条一句）
    "days": [{
      "title": "西安城墙 · 回民街",
      "text": "到西安，上城墙骑车，晚上回民街。",   // 以“从X坐/去/到…”开头会被当成“怎么去”的写明出发点
      "start": "13:00",            // 可选：这天几点出发（默认 09:00 左右）
      "city": "兰州",               // 可选：这天换了城市才写
      "stay": "钟楼附近",            // 可选：今晚住哪（片区名）
      "lunch":  {"dish": "…", "place": "…"},   // 可选
      "dinner": {"dish": "…", "place": "…"},   // 可选
      "stops": [{
        "name": "西安城墙",          // 显示名
        "q": "西安城墙 永宁门",       // 查坐标 / 搜索用的词（坐标表按 “城市|q” 找）
        "type": "sight",           // sight / park / street / museum / fun
        "dur": 150,                // 停留分钟
        "via": "地铁约 40 分钟",      // 从上一站怎么过来（**每天第一站必须写**）
        "at": "18:30"              // 可选：定点（看日落、表演、开门）
      }]
    }]
  }
}}
```

## 2. 列表卡片 `data/catalog/trips.json`

每条行程一张卡：`id, dest, name, region, days, title, headline, dek, why, price{lo,hi,currency,basis}, tags[], season{ok:[MM-DD,MM-DD], best:[MM-DD,MM-DD]}, anytime, status, page, engineRoute, poster`。
`price` 由 `tools/estimate_prices.py` 回填（新加时写 `None`）。`season` 决定走哪儿里“正好去 / 也行”。

## 3. 目的地 `data/destinations.json`

`{domestic:[34], asia:[22], world:[26]}`，每项：`id, name, region, base（主城）, q, cc（国家码）, best[月份 1–12], days, see[], eat[], visa, routes[行程 id], page, tip`。
`region` 用于走哪儿分区：国内（华北…港澳台）、亚洲（东亚、东南亚、南亚、西亚、中亚）、更远（欧洲、北非、非洲、北美、拉美、大洋洲）。分区顺序表在 `tools/build_catalog.py` 的 `REG`，**新地区名要先加到这里**。
`data/catalog/destinations.json` 是生成出来的（`build_catalog.py`），不手改。

## 4. 坐标和气候

- `data/geo/pois.json`：键 `"城市|q"` → `{lat, lng, hit, q, src}`；新加景点人工给近似坐标，`hit: "人工核对（近似）"`, `src: "curated"`
- `data/geo/destinations.json`：目的地 id → `{lat, lng, elev, src, clim: {"1":[白天, 夜里], … "12":[…]}}`
- 估价：`tools/estimate_prices.py` 里 `ASIA_AIR / ASIA_STAY / ASIA_FOOD`（国外新国家要加）

## 5. 纪录片

- `data/catalog/shejian.json`：《舌尖上的中国》
- `data/catalog/docs_more2.json`：老广的味道、如果国宝会说话第二至四季、话说长江、新丝绸之路、中国影像方志；**由 `tools/gen_docs_more2.py` 生成**（改数据改那个脚本和 `tools/yx_data.py`，别手改 JSON）。出处是中文维基百科各节目的分集表，地点对不上的不收
- `data/catalog/dish_note.json`：{原菜名: 带括号说明的菜名}，417 条（子代理凭记忆写，没核实），`compile_itineraries.py` 出每顿饭时替换；外地人看不懂的菜名加说明，一看就懂的不加
- `data/catalog/prov_food.json`：81 个省区市、国家的特色菜清单（子代理凭记忆写，没核实）；没写明午饭晚饭的天，`compile_itineraries.py` 按“城市招牌菜 → 纪录片拍过的本地吃的 → 本省/本国特色菜（按路线编号错开）→ 泛称”挑，**同一条行程里一道菜只出现一次**；带别的城市名的菜（芝加哥深盘披萨）不推荐给不在那座城的行程（`CITY_TAGS`）
- `tools/verify_auto_geo.py`：用 Nominatim 核对批量补进来的路线坐标（`query` 查、`apply` 改；`FOREIGN=1` 核对国外）；结果在 `build/`
- `tools/add_routes_json.py`：把“路线 JSON”（`data/auto_routes/*.json`）批量加进行程；条目没排进行程时用它补
- `data/catalog/why.json`：每个条目一句“好在哪、为什么要吃要去”，键 `片名|food|place`，片子页（`.why`）显示；820 条由子代理凭常识写成，**没逐条核实**（Jerry：“可不可靠不重要，先有”），以后可抽查；新增条目没有这句时页面就不显示这一行
- 片子封面：`tools/posters/gen_shows.py` 生成 `site_src/posters/show-<slug>.svg`（21 张，和行程海报同一套画法），片子页顶部和跟片走目录右侧用；走哪儿卡片缩略图用该目的地第一条线的海报
- `data/catalog/docs_travel.json`：旅行类（菲尔来蹭饭、未知之旅）和杂志榜单（孤独星球年度榜、国家地理年度榜；`MAG`，`ep` 写“2027 年榜”），由 `tools/gen_docs_travel.py` 生成，出处英文维基百科分集表
- `data/catalog/docs_more.json`：其他十部，每条 `{show, s(季), ep(集或空), food(吃的 / 国宝 / 课文), place, prov, keys[匹配行程用的词]}`
- 片子列表、地址和动词在 `build_site.py` 的 `SHOWS`；一句话说明在 `SHOW_NOTE`；`_eat` 决定标题是“去吃”类还是“地方”类；`SINGLE_SEASON` 决定哪些片子不写“第几季”；`food == place`（片里讲的就是这个地方）时只写地方，不重复括号

## 6. 门票、酒店、其他

- `data/catalog/tickets.json`：景点门票、要不要预约、官网
- `data/hotels/ctrip_hotels.json`：住宿推荐（三档）
- `data/catalog/cn_5a.json`、`cn_heritage.json`、`culture.json`、`city_food.json`、`niche.json`：目的地页用

## 7. 写在代码里的内容（`tools/build_site.py`）

| 名字 | 是什么 |
|---|---|
| `SIGHT` | 景点一句话：`'名字': '一句话'`（新景点的介绍加在这里） |
| `DEEP` | “懂一点”补充段：`'名字': '一段来历'` |
| `ORIGINS` | 默认出发城市和坐标（“怎么去”按最近的算） |
| `NO_HSR` | 不通高铁的旅游地（不写“坐高铁”） |
| `TRANSIT` | 北京上海没直飞、要转机的国家 |
| `SHOWS` / `SHOW_NOTE` | 纪录片频道 |

## 8. 编译产物 `build/routes.js`

`window.ZOUNI_ROUTES = {id: {label, price, driveTop(不开车/包车/自驾), days:[{title, text, city, navCity, lat, lng, stayName, rows:[…]}]}}`
每行 `rows[]`：`type`（`dep` 出发 / `see` 景点 / `fun` 玩 / `eat` 吃），`t`（"HH:MM"）、`name`、`to`、`how`（路上怎么走，**不是 via**）、`poi`、`dur` 等。

## 9. 页面里嵌的数据（`site.js` 读）

- 行程页 `data-go='{…}'`：`o`（默认出发城市）、`km`、`ab`（出国）、`drv`、`car`（第一天就要包车 / 大巴）、`nh`（不通高铁）、`isl`（海南）、`dst`（目的地 id）、`fx`（写明的出发点文字）、`legs`（中途换城市的车票：`[第几天, 从, 到, 火车票/机票]`）
- `<script id="cands">`：加一天的候选 `[{rid, label, i, title, lat, lng, d:{"第几天(从0)": 公里}, km}]`
- 每天 `<section class="day" id="dN" data-city="…">`；网页再加 `data-oi`（原来第几天）、插入的天有 `data-extra`、`data-after`

## 10. 用户手机上存的东西（localStorage）

`zouni:origin`（出发地）、`zouni_start_<id>`（出发日期）、`zouni_n_<id>`（几人）、`zouni_extra_<id>`（加的天，含 `after`）、`zouni_rmday_<id>`（去掉的天）、`zouni_adj_<id>`（改的出发时间）、`zouni_todo_<id>`（要办的事打勾）、`zouni_fav`（收藏）、`zouni_booked`、`zouni_where`、`zouni_hist` 等。改字段格式要兼容旧数据。
