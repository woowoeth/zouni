## 附录 · 红线（历史踩坑，写死）

1. **老内核语法**：微信安卓 X5 / 老 iOS Safari 不认 `?.` `??` `replaceAll` `.flatMap` `.at()` —— 一个字符就能让整页脚本拒绝执行、看起来"一直在报错"。静态终检第⑤项自动拦。
2. **补丁工程**：批量改文件必须"两阶段"——先全部锚点预检（count==1），全过再统一替换写盘；任何 assert 失败 = 整轮不写盘，杜绝半成品克隆段。
3. **数据结构**：新路线只写 Schema v2 三件套（transport / locale / stay），旧字段由 normRoute 自动反写，不要手写 rent/perCar/nav/nights。
4. **价格出现两处**（路线 budgets + 首页卡片文案）→ 改预算必须同步卡片，静态终检第⑥项自动对账。
5. **每晚住宿链**：lodges 项数必须等于天数（末天 null），错位 = 费用少算一晚，引擎仿真自动拦。
6. **i18n 双写**：新增任何 UI 文案必须 zh/en 同时进字典（静态终检第⑦项拦截单边）；新路线的 name/dest/title/meta/why 建议同步写 `i18n:{en:{...}}` 覆盖层；行程内容层（days/stops）翻译单独排期，英文态由提示条兜底。
7. **组件统一层**：同类功能必须复用同一组件语言——区块小标题（eyebrow/feed-sect/search-section-head/cs-label）四合一规则在 CSS 尾部「组件统一层」；选择件选中态一律 ink 实心白字（小件）或 2px ink 描边（带描述的大格子）；导航文字按钮（返回/取消）同级同貌；线路行标题 15px/700、说明 11px/ink-50/tabular-nums 三处（首页卡/搜索结果/行程卡）强制一致；空态统一结构。新增 UI 先查统一层能否复用，不允许再开第五种小标题。
8. **函数名 `t` 是 i18n 保留字**：任何函数内不得再声明局部变量 `t`（会遮蔽翻译函数，renderTotals 已踩过）。
9. **删 CSS 必须整条规则删**：用正则批量清 CSS 时，孤儿声明块（选择器没了、声明和 `}` 还在）会让浏览器吞掉后面的整条规则——本次 add-trip-card 布局崩即此因。删除后必须跑第 6 项视觉回归确认。
10. **用户输入进 innerHTML 必须 esc()**：搜索词、历史词、任何将来接自由输入的字段，插模板前一律 `esc()` 转义（已在工具层提供）；七连测第 4 项含注入攻击串回归。
11. **裁切容器内的元素用内描边**：折叠动画容器带 `overflow:hidden/clip`，会裁掉紧贴边缘元素的 `box-shadow` 外描边（表现为"左边一列按钮没有边框"）。此类元素（`.pchip` 等）一律用 `box-shadow:inset`，hover/focus 态同步 inset。
12. **对比度是硬指标**：`--ink-50` 已调到 WCAG AA 4.5:1（白底 5.0 / 纸底 4.57），承载信息的文字一律用 ink-50 或更深；`--ink-30` 只允许用于装饰、图标、禁用态与被跳过项，不得承载用户需要读的信息。
13. **焦点环必须兜底**：全局 `:focus-visible` 会被后定义的组件 `box-shadow` 覆盖，样式表末尾用 `button:focus-visible` 一类更高特异性的规则兜住（第 9 项用真实 Tab 键验证，JS `focus()` 不触发 `:focus-visible`）。
14. **jsdom 测不了排版**：任何布局/结构改动，第 6 项视觉回归是唯一防线，改完必跑必看截图。
15. **localStorage 结构变更**：升 `v` 字段并在 restoreLS 里做旧版兼容或安全丢弃，禁止直接改字段含义。

### ⚠ 发布频率纪律（踩过的坑）

GitHub Pages 有**构建配额与队列**：同一小时内推送十余次后，构建会开始失败或长时间排队，表现为：

| 现象 | 含义 |
|---|---|
| `status: errored` + `duration: 0` + 错误只有 "Page build failed." | 配额耗尽，**与代码无关** |
| `status: building` 持续数分钟不结束 | 队列拥堵，等待即可 |
| 线上文件仍是旧版但 API 显示推送成功 | 构建未完成，或 CDN 缓存（HTML `max-age=600`，10 分钟） |

**纪律**：
1. 每轮改动**攒齐再发**，不要为单个小改动反复推送
2. 遇到构建失败，**先查是不是配额**（`GET /repos/{o}/{r}/pages/builds/latest` 看 duration 是否为 0），不要急着怀疑代码
3. 验证线上版本时带 cache-buster（`?cb=时间戳`），并直连 `*.github.io` 排除自有域名 CDN 缓存
4. 教训记录：曾因此误判「文档目录导致构建失败」，做了多轮无效排查；实际是配额耗尽，配额恢复后同样的文档推送即成功

## 四、发布操作（GitHub Pages · 一次 token，之后一条命令）

1. **一次性 token**（仅首次）：打开 https://github.com/settings/tokens/new?scopes=repo&description=quickship → Generate → 复制 `ghp_...`
2. **发布**（把 TOKEN 换成你的）：
```bash
GITHUB_PUBLISH_TOKEN='ghp_xxx' python3 /tmp/quickship_publish.py --dir zouni-site --name zouni
```
3. 输出 `LIVE_URL https://<你>.github.io/zouni/` 即上线（首次构建约 1 分钟）；重跑同名 = 覆盖更新。
4. **上线后真机点检**：微信里打开 LIVE_URL 过一遍「二、人工真机点检」全部项；iOS Safari 分享→添加到主屏，确认独立图标与离线打开。
5. 微信内 github.io 若不可达：把 `zouni-site/` 目录原样上传任意国内静态托管/自有域名即可，无需改代码。
