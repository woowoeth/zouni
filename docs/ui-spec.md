## 零、三条元规则

1. **brief 优先**。外部规范提供判据，不改我们的视觉语言。碱白规范说了算。
2. **只看不测等于没读**。任何外部判据都要写脚本跑在我们产品上，再决定采不采纳。
3. **修完必须进守卫**。一条判据如果不能变成自动断言，它迟早会回退。

## 二·五、色彩

用 **APCA**（感知对比算法）而非只看 WCAG——它更贴近人眼实际感受，且与 OKLCH 同源。

| Token | 值 | OKLCH | 用途 | APCA（纸底） | 阈值 |
|---|---|---|---|---|---|
| `--ink` | `#2a2e2c` | L .296 | 正文标题 | **Lc 91.3** | ≥75 ✓ |
| `--ink-70` | `#4c524e` | L .432 | 次要文字 | Lc 78.7 | ≥60 ✓ |
| `--ink-50` | `#686e68` | L .531 | 说明文字 | Lc 66.9 | ≥60 ✓ |
| `--ink-30` | `#a3a8a1` | L .725 | 仅装饰/禁用 | Lc 38.6 | ≥30 ✓ |
| `--up` | `#57673f` | L .548 | 正向语义标签 | **Lc 71.6** | ≥60 ✓ |
| `--down` | `#994a40` | L .568 | 警示语义标签 | **Lc 71.2** | ≥60 ✓ |
| `--sulfur` | `#b8c49a` | L .786 | 主按钮填充 | Lc 25.5 | ≥15 ✓ |

**阈值按用途分级，不能一刀切**：正文 75、非正文 60、装饰 30、非文字元素 15。把 10px 的语义标签按"正文"要求会误判。

**这轮改了什么**：`--up` 与 `--down` 提亮度对比（Lc 64 → 71.6 / 63.5 → 71.2，WCAG 4.18 → 5.38）。做了三方案对比截图：压到 Lc 76 时红色发褐、绿色发闷，损失碱白的清透；Lc 71 是清晰度与气质的平衡点。

**两处记录在案的例外**：

| 现象 | 为什么不改 |
|---|---|
| 中性色相跨度 58°（白 106° → 墨 164°） | 碱白的墨色刻意带冷绿，越深越明显。这是品牌特征，不是调色板漂移事故。守卫阈值放宽到 90° |
| 主按钮底 Lc 25.5 < 30 | 它是填充不是文字。**压暗到 30 反而让按钮上的字从 Lc 63.6 掉到 58.4**，是负优化。按钮自带形状与文字，非文字元素底线 Lc 15 已远超 |

## 三、组件与交互

| 判据 | 我们的取舍 |
|---|---|
| **按压反馈** | 所有可点元素 `scale(0.96)`；大面积卡片收敛到 `0.985`（整块缩会晕） |
| **可中断动效** | 交互态一律 CSS transition，keyframes 只留给一次性入场（描线动画） |
| **动效时长** | ≤300ms，`ease-out` |
| **同心圆角** | 判据说"外 = 内 + padding"。我们**刻意不遵守**一处：卡片 12px + 内边距 15px，内层选项行仍用 8px——按公式该是 0，但实测视觉更干净。**记录在案的例外，不是疏漏** |
| **阴影与边框** | 阴影表达层级，边框表达结构（分隔线、选中态） |
| **裁切容器内用内描边** | 折叠/横滑容器会裁掉外描边，一律 `box-shadow: inset` |
| **选择件语言** | 小件选中 = 墨色实心白字；大格子选中 = 2px 墨色描边 |

## 三·五、滚动与视觉稳定

**用户在页面中段操作时，视觉位置不能被拽走**——这是移动端最容易被忽视的体验缺陷。

| 机制 | 做法 |
|---|---|
| 天签横滑 | 只改横滑条自身 `scrollLeft`。**禁用 `scrollIntoView`**——它即使带 `block:'nearest'` 也会连带滚动整个页面 |
| 内容高度变化 | `keepScrollAnchor()`：重绘前记录视口内锚点元素与视口顶的距离，重绘后 `scrollBy` 补回。切天、加站、重排都走这条 |
| 首次生成 vs 重排 | 从首页首次生成才滚到顶部；已在详情页内的任何操作都保持位置 |
| 吸顶天签 | `position:sticky`，`top` 取 `--mh-h`（顶栏实测高度，随标题行数变化，ResizeObserver 同步）；文字 `align-items:center` 精确居中（上下各 11px） |
| 行程时间轴 | **不占独立列**。原来左侧 46px 固定列吃掉 13% 宽度、把卡片压到 298px；改成时间以小字排在卡片上方，卡片吃满 354px（**+19%**） |

**排查方法**：不能只测 `window.scrollY` 有没有变——高度变化时 scrollY 不变但内容会滑走。要测**锚点元素相对视口的位移**。

## 三·六、尺寸阶梯与间距节律

实测发现 70 个按钮混着 **13 种高度**（27/30/33/34/36/40/44/45/55/56…）、3 种圆角、4 种字号——这就是"按钮大小不一致"的来源。收敛为三档：

| 档位 | 高度 | 字号 | 用在哪 |
|---|---|---|---|
| **小** | 28px | 11px | 行内动作：**导航**、现在出发、记入下次、跳过、看点、修改行程 |
| **中** | 36px | 12px | 独立操作：遇上下雨、恢复原计划、微调、语言货币、返回 |
| **大** | 44px | 13–14px | 主要动作：安排行程、复制链接、待办行、二选一 |

圆角一律 **8px**（胶囊型 pill 除外）。小档视觉 28px 但用伪元素把触达补到 40px。

**行高按角色分级**（原来一律 1.55，短句会显得松散）：

| 类型 | 行高 | 说明 |
|---|---|---|
| 段落型（一句话卖点、为什么这样排） | 1.5 | 需要连续阅读 |
| 说明型（备选理由、费用尾注、接驳副标） | 1.45 | 多为 1–2 行短句 |
| 单行型（接驳主行） | 1.4 | 几乎不换行 |

**信息分层优先于挤在一行**。接驳行原本把「多远多久 + 从哪到哪 + 沿途提示」三层信息塞进一行，文字换到三行时按钮孤悬右侧。改为两行结构：

```
🚗 480 km · 约 6 小时 50 分            [导航↗] [现在出发]   ← 主行：核心数据 + 动作，永不换行
   乌鲁木齐 → 可可托海                                    ← 次行：路线
   沿途 · 火烧山雅丹（停 20 分）· 中途换驾一次              ← 三行：提示，字号更小
```

主行用 `white-space:nowrap` + `text-overflow:ellipsis` 保证不换行，按钮永远在同一水平线；完整描述下沉后占满宽度自由换行。**一行只放能一眼扫完的东西，其余下沉。**

**间距要查清是谁贡献的**。「今晚住」标题上方 30px 过大，标题自身 margin 只有 14px——多出的 16px 是前一个接驳块的下内边距。相邻两个元素的间距往往由**双方共同贡献**，只改一边不解决问题。

**改布局前先查清有几种结构**。接驳行实际有两套 DOM：路段接驳是 `conn-head(核心数据+按钮) + conn-main(描述)`，住宿提示行只有 `conn-main + conn-acts`。我一次性把 `.conn` 从 flex 改成 block，路段接驳对了，住宿行的按钮却掉到下一行。现在用 `:has(.conn-head)` 分别处理两种结构。

**后续内容嵌套在接驳块内部**（DOM 是嵌套不是兄弟），所以相邻兄弟选择器 `.conn + .t-col` 完全够不着，间距一直是 0。必须用后代选择器 `.conn .t-col`。**改间距前先确认 DOM 是嵌套还是并列。**

**行内对齐**：文字与右侧按钮必须同一中线。接驳行原用 `align-items:flex-start`（文字顶对齐）而按钮容器内部是 `center`，两者中线错开——看起来就是"没在一行上"。整行统一 `center`。

**间距节律 4 / 8 / 12**，卡片内不再出现 7px、10px 这类零头。行程流的层级间距：时间行→卡片 6px（成组）、卡片→接驳 14px、接驳→下一个时间行 16px。

## 三·七、行程卡：封面即导航入口

行程页只放**用户自己保存的行程**，不放设计稿——演示数据混在真实数据里，用户分不清哪个是自己的。

每张行程卡带 52px 封面（复用线路封面数据，零额外体积），**封面本身就是导航按钮**：

| 交互 | 行为 |
|---|---|
| 点封面（含「导航 ↗」角标） | 直接唤起高德，目标是该线第一个有导航词的站点 |
| 点卡片其余部分 | 打开这份行程 |

唤起策略：先试 App scheme（iOS `iosamap://` / Android `androidamap://`），1.1 秒内页面没切走就回退到高德网页版 `uri.amap.com`。事件用捕获阶段 + `stopPropagation`，确保点封面不会误触发"打开行程"。

## 三·七·五、导航入口：只在站点卡里出现一次

**接驳行不放导航按钮**。原来「步行到八廓街」「打车前往色拉寺」这类接驳行右侧各有一个导航，与紧随其后的站点卡里的导航重复——同一个目的地出现两个入口，用户不知道点哪个。现在只在站点卡内保留。

**行程卡封面是纯展示图，不做导航入口**。列表页的图片是用来认出这是哪趟旅行的，不承担动作。

**导航按钮直接起导航，不是打开搜索页**：

| 平台 | 唤起方式 |
|---|---|
| Android | `androidamap://keywordNavi?keyword=…&style=2` —— 关键词直达路线规划 |
| iOS | `iosamap://poi?keywords=…` —— 高德未开放关键词直导，退而唤起地点页 |
| 回退 | `uri.amap.com/navigation?toname=…&callnative=1` 网页版 |
| 国外线路 | Google Maps `dir/?api=1&destination=…` |

## 三·八、行程去重与版权署名

**同一个目的地只保留一份行程**。天数变体（`xz7` / `xz10`）在数据层是不同的 routeId，但对用户来说是同一趟旅行改了天数——**按线路族去重，不是按 routeId**。改天数、改预算、换住宿都是在改同一份行程，原地更新并提到最前，不堆卡片。

**署名不放卡片上，集中到「我的 → 图片来源」**。

需要说明的是：CC BY / CC BY-SA 的署名要求**与商用与否无关**，非商业使用同样要标。所以署名只能换位置、不能省略。做法是逐条列出线路对应的作者与许可证，地图统一标 © OpenStreetMap（ODbL）。这样卡片视觉干净，合规也没丢。

## 三·九、界面细节：六条铁律（第 18 项守卫）

这六条都是真机反馈逼出来的，现在每条都有自动断言，跑遍全部线路的全部天数，不抽样。

| 铁律 | 反面案例 | 判据 |
|---|---|---|
| **短内容不分两行** | 「10 分」+「步行回住处」硬拆成两行，反而更散 | 两截合计 ≤16 字且无第三行 → 必须合并 |
| **不留空行占位** | 主行为空、内容全在次行，上面白白空一行 | 主行空则整段提到主行 |
| **同层左缘对齐** | 嵌套 padding 层层累加，越往下越偏右（实测 20/22/24/26px） | 同一天所有接驳行基准线必须唯一 |
| **文字与按钮同中线** | `align-items:flex-start` 让文字顶对齐、按钮居中 | 中线偏差 ≤6px |
| **同一目的地只给一个入口** | 接驳行和站点卡各有一个导航按钮 | 接驳行不得出现导航 |
| **同类按钮尺寸统一** | 70 个按钮曾有 13 种高度 | 行内按钮高度种类 ≤2 |
| **弹层按钮不被 tab 遮挡** | 底部 tab 是 `z-index:200`，弹层只有 60 —— 关键按钮点不到 | 弹层 z-index >tab，且打开时隐藏 tab |
| **同层标题左缘一致** | 「先挑一条」在 20px、「长线 · 高原雪山」因带内边距落在 34px | 首页所有 eyebrow 与 feed-sect 文字左缘唯一 |
| **不出现 24:00 以上的时间** | `Math.floor(m/60)` 不回绕，深夜点「现在出发」算出 25:01 | 时间格式化对 1440 取模 |
| **区块间距不累加** | 嵌套结构每层都给内边距，5 层堆出 50px 空白 | 相邻区块间距 >24px 且中间无内容 → 失败 |

**分层 vs 合并的判断不能一刀切**——我最初把接驳行统一改成两行结构，长文案时确实清爽，短文案时反而把「10 分 / 步行回住处」这种一眼能读完的内容硬拆开。规则应该按实际内容长度自适应。

**量对齐要量文字，不能量容器**。我第一版守卫测的是 `.conn` 容器位置，全绿通过，但你一眼看出还是不齐——因为 A 结构的文字包在 `.conn-key` 里、B 结构直接跟在图标后，**多一层元素就多一次边界取整，差 2px**。必须用 `Range` 量第一个文字节点的实际坐标。

**两种结构要走同一套坐标系**。flex + gap 做不到（元素层数不同就会偏），改用 **CSS Grid 把「图标列 16px + 间隙 8px + 内容列」写死**，A/B 两种结构共用同一份列定义，对齐才是结构性保证而不是凑出来的。

**内边距只给内容行，容器层必须归零**。接驳块层层相套，若每层都写 `padding: 9px 0`，视觉上就会一路堆高——「今晚住提示行 → 今晚住标题」之间实测堆出 50px（5 层 × 9px + 标题 14px）。改成只给 `.conn-head` 和直接文字行加内边距、容器层归零后，降到 14px。

**嵌套 padding 是对齐的隐形杀手**。接驳块在 DOM 上层层相套（每个 `.conn` 里包着后续内容），每层 2px 内边距累加下来，第四行就偏了 6px——肉眼说不清哪里怪，但就是不齐。解法是内边距归零、图标用固定宽度的槽。

## 三·十、首屏空态：只留搜索框

没选目的地时，「几天/预算/口味」显示的是**上一条线路的参数**——摆在那里等于替用户做了决定，用户以为自己在配置，其实在改别人的行程。

空态下把配置区收到 0，只留搜索框（472px → 108px）。选了线路才展开。

**实现要点**：目的地行必须移出 `.sheet-acc`，否则折叠会连搜索框一起收掉。这是我改了四次才发现的——前三次都在调 CSS，没意识到结构本身有问题。

## 三·十一、三个"点了没反应"的坑

| 问题 | 根因 | 解法 |
|---|---|---|
| **设出发日期点了没反应** | 用 `input.showPicker()` 唤起原生日期控件，**iOS Safari 不支持这个 API** | 自建日期面板：列未来 60 天，各端一致 |
| **「修改行程」毫无价值** | 它只是展开配置区，但配置区就在下面一直可见 | 直接删掉 |
| **改了日期摘要没变** | 摘要条只在折叠态显示，展开态看不见 | 摘要条改为选了线路后常驻 |

**共同点**：三个都不是"功能没实现"，而是**功能实现了但用户感知不到**。写代码时看着都对，真机上就是"点了没反应"。

**教训**：涉及原生控件的 API（`showPicker`、`share`、`vibrate`）必须查兼容性，不能只在桌面 Chrome 测。

## 三·十二、配置区的三个状态

| 状态 | 高度 | 什么时候 |
|---|---|---|
| **空态** | 87px | 还没选目的地，只有搜索框 |
| **收起** | 127px | 已有行程 —— 一行摘要（线路 · 天数 · 预算 · 出发日） |
| **展开** | 427px | 点摘要条主动要改 |

| **详情页** | 427px | 看着行程调天数/预算/口味 —— **保持展开**，收起来反而要多点一次 |

**所有回首页的路径都要回空态**——底部 tab、左上角返回箭头、从行程页返回，一个都不能漏。
我这次就漏了返回箭头：`goHome()` 里写的是 `remove('collapsed')`，等于把配置区**展开**了，正好相反。
已加进第 18 项守卫逐条验证。

**点底部「首页」tab = 重新开始**：配置区回空态、行程结果收起、回到线路列表。
已排好的行程不会丢——它在「行程」tab 里，从那儿点回来能继续。

这个区分很重要：**「首页」是开始新计划的地方，不是"回到刚才那份"的地方**。后者是「行程」tab 的职责。

**默认收起，要改才展开**。用户一进来面对一整屏选项是负担，但完全看不到当前配置又心里没底——一行摘要是平衡点。

**横排后要清掉竖排时代的边距**。`.sheet-k`（「目的地」标签）原本是竖排布局的标题，带 `margin-bottom:6px`；改成 flex 横排后这个下边距变成无效的垂直偏移，把行顶撑高。加上 `.sheet-row` 的 `margin-top:12px`（`:first-child` 重置对它不生效——前面还有个隐藏的摘要条），一共多出 24px，看起来就是"上边距太高"。

**CSS 特异性要三态一致**：我给空态写了 `!important` 压到 `0fr`，结果把展开态也压住了，点摘要条没反应。三条规则（空态压 0 / 收起压 0 / 展开恢复 1fr）必须用同等特异性，否则总有一个态失灵。

**事件绑定要独立**：展开的点击处理最初挂在主点击处理器里，被前面的 `return` 挡掉了。改成独立的捕获阶段监听才生效。

## 三·十三、统计区：按关心程度排，不按数据类型排

原来是 2×2 网格：里程/天数在上，强度/人均在下。问题是**「3,058km」和「中」放在对角，视觉重量完全不平衡**，格子明明等宽，看着就是歪的。

改成：

```
¥8,757                    ← 独占一行，28px，主视觉
人均

12天      3,058km    中   ← 三项等宽并排，18px
11晚住宿  全程自驾   强度
```

两条原则：

1. **顺序按用户关心程度**——花多少钱最先，其次几天、多远、多累。不是按"数据类型"分组
2. **长短悬殊的值不并列**——「3,058km」和「中」宽度差 6 倍，放同一行会显得空。让最重要的独占一行，其余等宽

值全部左对齐（金额那行也是），四项左缘统一。

## 三·十四、次级动作不占主按钮区

「复制到微信」「保存」原本是两个 44px 的大按钮独占一块区域。但它们是**排好行程之后**才用的动作，不是主流程——放大按钮区等于抢了内容的位置。

改成：**28px 小按钮，跟在副标题右侧**，与顶部的语言/货币 pill 同一档尺寸，右缘对齐。

顶部语言/货币也从 36px 圆丸缩到 28px 圆角——它们是设置类入口，不该比内容操作还醒目。

**判断标准**：这个动作是"用户为了达成目标必须点的"，还是"达成之后可能会点的"？前者用大按钮，后者用小按钮。

## 四、布局

| 判据 | 我们的值 |
|---|---|
| 分组间距 | 组间 ≥ 2× 组内 |
| 单一缩进源 | 水平缩进只由 `.page` 提供，页内卡片 `margin: 0 0 10px` |
| 安全区 | `env(safe-area-inset-*)` 全覆盖 |
| 网格对齐 | 口味 4×2、预算 2×2、天数一行——等宽网格，不用 wrap 参差 |
| 统计区 | 前三列均分、金额列按内容宽贴右，三个间隙均等 14px |
| 内容增长 | 文本容器不设固定宽高，允许换行 |

## 五、文案

| 判据 | 我们的做法 |
|---|---|
| 按钮动词开头 | "安排行程"、"排进 D4"、"记入下次"；无"确定/好的/是/否" |
| 链接自解释 | 无"点这里"、"了解更多" |
| 错误平静具体 | "这条线路暂时打不开 · 已退回上一条"，不道歉不卖萌 |
| 不做假承诺 | 文案说"可加"就必须真能加——**静态终检第 8 项自动拦** |
| 一个词一个意思 | "安排行程"不会在别处变成"生成方案" |
| 语气分级 | 空态可暖，错误必须平静，数据丢失必须严肃 |

## 六、跨端（为小程序预留）

| 层 | 浏览器依赖 | 小程序 |
|---|---|---|
| 数据 + 引擎（148KB） | **零** | 直接搬，一行不改 |
| UI（56KB） | document 28 · innerHTML 33 · classList 35 | 按平台重写 |

**三条纪律**（第 13 项守卫）：引擎层禁用任何浏览器 API；平台能力（存储/分享/导航/剪贴板）只准出现在 UI 层且集中在少数函数；禁用 `?.` `??` `replaceAll` `flatMap` `at()` 等高版本语法。

## 附：实测中被判为「误报」的判据

自动检测容易冤枉人，这几类已在检测器里豁免，理由记下来免得反复：

| 现象 | 为什么不是问题 |
|---|---|
| 同组元素间距 6px < 8px | 判据说的是"不同组的相邻控件"，同组紧凑是设计意图 |
| 天签与底部 Tab 栏间距 2px | 一个是内容层一个是固定层，视觉重叠但不在同一平面 |
| 卡片 12px 套 8px 圆角 | 并列层级，不是嵌套关系；真嵌套要求内层撑满且有背景 |
| 按钮高度 16px | 伪元素已补到 44px 触达，视觉尺寸是刻意的 |
| 43/66 按钮 < 44px | 44px 是触屏建议值，24px 才是 AA 底线，我们全部达标 |
